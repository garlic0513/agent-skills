## 一、高质量纪要的 6 条标准

| # | 标准 | 落地写法 |
|:-:|------|---------|
| 1 | ⭐ 每个议题必须有**结论** | 结论只有三种：`同意` / `不同意` / `待定(→ OPEN)`。禁止只写"讨论了X" |
| 2 | ⭐ 每个待办有**责任人+期限** | Who / When / What 三件套，缺一个等于没记 |
| 3 | ⭐ 区分**四类内容** | 事实 / 观点 / 决策 / 待办 —— 分栏或加标签，不混写 |
| 4 | ⭐ 保留客户**关键原话** | 需求、承诺、验收口径引原话（加引号），避免日后扯皮 |
| 5 | ⭐ **当场复述 / 24h 内确认** | 纪要有效性靠双方确认，不靠文笔 |
| 6 | ⭐ **可追溯** | 编号·日期·参会人·议题号·引用的 URS 条款号/文档版本号 |

### 四不写

```
✗ 不写流水账（按谁先说话的顺序记）
✗ 不写没结论的讨论（要么给结论，要么进 OPEN）
✗ 不写主观评价（"客户不专业"）
✗ 不把推断当事实写（标"推断"+依据）
```

## 二、⭐⭐ 四维记录法（会中记录框架）

> ⭐ **完整方法见独立 skill：`research-4d-method`**（含四维度定义、每维度追问清单、记录表模板、三张输出清单）
> 本节只保留"会议场景下怎么用"

| 维度 | 英文 | 一句话 |
|:----:|:----:|--------|
| 现状 | AS-IS | 客户目前怎样开展工作（⭐ 重点记手工动作与纸质单据） |
| 目标 | TO-BE | 客户希望新系统实现什么（记原话 + 背后诉求） |
| 差异 | GAP | 标准功能能否满足 → ⭐ 三选一：能（标准）/ 部分（需配置）/ 不能（需定制） |
| 待确认 | OPEN | 哪些问题没定 → ⭐ 必须带**责任人 + 期限** |

```
会议中的用法：
1. 每个议题按四维展开记录（现状→目标→差异→待确认）
2. 议题结束前必问："这条咱们定了吗？" → 逼出结论
3. OPEN 项当场问出责任人和期限
4. 会后四维表 → 三张清单（需求 / 选项 / 风险）→ 附在纪要后
```

### ⭐ 缺失关键信息的追问清单（现场照着问）

```
现状 AS-IS：谁做的？几步？用什么工具？（纸质/Excel/旧系统/口头）
           ⭐ "能不能给我看一下现在用的表？"
目标 TO-BE："上了系统后第一步变成什么？" / "如果只能实现一个，你先要哪个？"
差异 GAP  ：标准产品有现成的吗？差不多但要调？完全没有？
           ⭐ "如果标准产品是另一种做法，能接受吗？"
待确认 OPEN："这条谁定？什么时候给答复？拖着不定会卡住什么？"
```

### 与流程图方法的衔接（闭环）

```
调研四维记录法            全分支流程图工作法
  现状 AS-IS  →  流程图"主干"
  目标 TO-BE  →  流程图"推荐路径"
  差异 GAP    →  流程图"可选分支 / 需定制点"
  待确认 OPEN →  流程图【待确认菱形】+ 右侧选项面板

闭环：调研四维 → 流程图分支 → 会上剪枝（客户勾选）→ 定稿
```

## 三、纪要结构模板

```
1. 会议基本信息
   （名称·日期时间·地点·客户方参与人·我方参与人·记录人）
2. 会议目的与议题（1~3 条，写清"本次要解决什么"）
3. ⭐ 各议题记录（按议题分块）
   议题N：xxx
     · 讨论要点（事实/观点分开）
     · 客户原话（引号）
     · ⭐ 结论：同意 / 不同意 / 待定
4. ⭐ 决议事项（Decision Log）
   编号 | 决议内容 | 决策人 | 生效条件
5. ⭐ 行动项（Action Log）
   编号 | 事项 | 责任人 | 期限 | 交付物 | 状态
6. ⭐ 待确认项（OPEN Log）
   编号 | 问题 | 责任方 | 期限 | 对项目的影响 | 状态
7. 附件与材料清单（流程图/文档名称 + ⭐ 版本号）
8. 下次会议安排
```

> 可直接复制的空白模板见 `templates/meeting-minutes.md`

## 四、💊 GMP/CSV 场景的额外要求（药企项目）

```
⭐ 药企项目的纪要 = 需求确认的证据，不只是会议记录

① 引用 URS 条款号 → 形成"需求 ↔ 设计 ↔ 测试"追溯链
② 版本化 + 双方确认（邮件/签字），注明版本与生效日期
③ 变更留痕：谁改的 / 为什么改 / 影响哪些文档
④ 涉及合规判断的表述要谨慎（"待QA确认"而不是自行判定）
⑤ 服务于：21 CFR Part 11 / EULA Annex 11 / GAMP 5 的"可追溯性"要求

⭐ 差异化价值：别人写纪要，你写"可审计的纪要"
```

## 五、标准工作流（会前 / 会中 / 会后）

### 会前（10 分钟准备）

```
1. 拉上次纪要的 OPEN 项 → 本次先过一遍（闭环检查）
2. 准备议题清单（1~3 条，别贪多）
3. 打开四维记录表 + 空白纪要模板
4. 准备要展示的材料（流程图/文档，⭐ 记好版本号）
```

### 会中（边听边填）

```
1. 用四维表逐条记录（现状/目标/差异/待确认）
2. ⭐ 客户原话打引号原样记
3. 每个议题结束前问一句："这条咱们定了吗？" → 逼出结论
4. OPEN 项当场问责任人和期限
5. 记录参会人 + 材料版本号
```

### 会后（当天内）

```
1. 四维表 → 三张清单：
   · 需求清单（目标 + 差异中"能/需配置/需定制"）
   · 选项清单（需客户决策的差异项 → 做成 A/B 选择题）
   · 风险清单（OPEN 项，带责任人+期限）
2. 出正式纪要（按第三节结构）
3. ⭐ 24h 内发出，请对方确认（邮件/会议系统留痕）
4. 更新流程图（差异→分支，OPEN→待确认菱形）
5. 归档到知识库，命名：`YYYY-MM-DD 会议名称.md`
```

## 六、常见错误（陷阱）

| 陷阱 | 后果 | 正解 |
|------|------|------|
| 写成流水账 | 没人看，翻不到结论 | 按议题分块，每块给结论 |
| 只记"待确认"，不记责任人和期限 | 永远悬着，最后变成扯皮 | ⭐ 当场问责任人和期限 |
| 差异项不写"标准/配置/定制" | 报价和工期没依据 | ⭐ 三选一必填 |
| 把推断当事实 | 后续被追责 | 标"推断"+依据 |
| 纪要写完不发/不确认 | 等于没写 | 24h 内发出并请确认 |
| 不记材料版本号 | 后期对不上哪一版流程图 | ⭐ 附件必须带版本号 |
| 客户情绪/潜台词不记 | 丢掉重要信号 | 写在"我的记录"里，标注为主观判断 |

## 七、快速自查清单（发出前过一遍）

```
□ 每个议题都有结论？（同意/不同意/待定）
□ 每个行动项都有 责任人 + 期限 + 交付物？
□ OPEN 项都有 责任方 + 期限？
□ GAP 项都写了 标准/配置/定制？
□ 客户关键原话引了吗？
□ 附件版本号写了吗？
□ 参会人/日期/记录人齐了吗？
□ 有没有把推断写成事实？
□ 24h 内能发出去吗？
```
