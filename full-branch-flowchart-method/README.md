# 全分支流程图工作法 · Full-Branch Flowchart Method (FBF)

> **把流程图当成决策树来画 —— 预置客户所有可能的分支，会上和客户一起「剪枝」。**

## 要解决的问题

做流程梳理/需求调研时，传统做法是：

```
我方画一条标准流程 → 客户看 → 客户提差异 → 我方改 → 再提 → 再改（3-5 轮）
```

问题在于：**让人指出「缺什么」很难，让人回答「要不要」很容易。**

## 方法的转变

```
我方预置【全分支树】（覆盖所有可能）→ 会上客户【剪枝】→ 一轮定稿
```

## 三个底层判断

```
① 流程图本质 = 决策树（每个判定点 = 一次分叉）
② 客户"选"比客户"想"容易（选择题的认知负担远低于开放题）
③ 我方的专业价值 = 帮客户看见他自己没想到的可能
```

## 核心亮点

- ⭐ **四步法**：建分支库 → 画全分支树 → 会上剪枝 → 定稿
- ⭐ **视觉体系**：主干实线 / 待确认橙虚线 / 菱形三出口（下=是・右=否・左=其他）
- ⭐ **18 条通用判定点分支库**（可直接当检查清单过一遍）
- ⭐ **绘制铁律（两层）**
  - **路由层**（怎么画不穿框，任何模板都适用）：先定泳道 → 再排节点 → 最后连线；全局顺序定 y；菱形左右・矩形上下；水平走行间隙／垂直走泳道走廊；待确认选项放最右侧
  - ⭐ **交付层（对齐客户/公司既有模板）**：角色泳道 vs 系统泳道 · 顺序编号（10/20/30）vs 层级编号（1/8.1）· 分页下钻 vs 单张全景 · 颜色语义 · 系统归属用小标签
- ⭐ **树状编号体系**（1.3.a）——图、清单、文档三处对应，会上说一个编号三方都懂
- ⭐ **交付前自查清单**：动笔前解析模板 → 画的过程中对齐 → 出图后几何验证 → 内容校验


## 什么时候用

- 乙方实施顾问：需求调研、业务蓝图、流程确认
- 客户无信息化经验（不知道自己能要什么）
- 客户流程尚未定型（还在梳理中）
- 有大量「多方案可选」的判定点

⚠️ 不适合：客户已有成熟固定流程 / 流程极简单无分支 / 客户明确拒绝被引导。
