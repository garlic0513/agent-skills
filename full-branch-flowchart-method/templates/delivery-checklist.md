# 流程图交付自查清单 · 对齐客户/公司模板

> 用途：把图画完、发出去之前，逐条过一遍
> ⭐ 核心原则：**方法（怎么想全分支）不退让，格式（怎么画出来）全听对方。**

---

## 一、动笔前：解析模板（没做这一步就先别画）

- [ ] 已拿到对方的**标准流程图原件**（.drawio / .vsdx / .eddx / PPT 截图）
- [ ] 已确认：泳道是**角色**还是**系统**？
- [ ] 已确认：节点**有没有编号**？编号是**递增（10/20/30…）**还是**层级（1 / 8.1 / 9.1.1）**？
- [ ] 已确认：**系统归属**怎么表达？（泳道 / 节点旁小标签 / 颜色）
- [ ] 已确认：有没有**分页下钻**（主流程 → 子流程）？
- [ ] 已确认：**颜色语义**是什么？（蓝=系统动作？灰=线下动作？）
- [ ] 结论已写成一张「模板规范对照表」

## 二、画的过程中

- [ ] 泳道按对方标准划分（角色 or 系统）
- [ ] 节点文字格式一致（如「序号 + 动作」，序号在句首）
- [ ] 判定节点用菱形，出口标签（是/否）齐全
- [ ] 子流程用双线框，并确认对应页存在
- [ ] 开始/结束用胶囊形，全图只一个入口
- [ ] 颜色只用于表达**一层含义**（别一图多语义）
- [ ] 我方独有内容（待确认面板、图例、备注）→ 另附文档，别硬塞

## 三、出图后（技术校验）

- [ ] **几何验证**：逐条线段与节点矩形求交 → **0 处穿框**
- [ ] 连线标签有**白色底色**（防重叠）
- [ ] 没有孤立的悬空节点（除开始/结束）
- [ ] 每个判定节点都有 ≥2 条出口，且都有出口标签
- [ ] 每个分支都能走到「流程结束」（没有死路）
- [ ] 跳过的子流程页都已生成

## 四、交付前（内容校验）

- [ ] 每个节点都能回答「谁做 / 在哪个系统做 / 线下还是线上」
- [ ] 待确认项已汇总成《选项清单》（带责任人和期限）
- [ ] 图上的编号与《选项清单》《流程说明》的编号**三处一致**
- [ ] 版本号 + 日期写在图名或页脚

## 五、常见翻车点

| 翻车 | 后果 | 防法 |
|------|------|------|
| 用自己那套格式直接交付 | 客户要求全部重画 | ⭐ 先要模板 |
| 编号规则混用（层级 + 递增） | 会上说不清"第几步" | 一页一规则 |
| 判定节点滥用 | 图爆炸、客户看不懂 | 只对"走法不同"的分叉用菱形 |
| 子流程框没有对应页 | 客户问"这个子流程在哪" | 交付前点数 |
| 待确认项塞在图里 | 图变脏、定稿后删不干净 | 另附选项清单 |
