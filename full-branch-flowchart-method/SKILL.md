# 全分支流程图工作法（FBF）

> ⭐ 一句话：**把流程图当成决策树来画 —— 预置客户所有可能的分支，会上和客户一起剪枝。**

## 何时使用

- 乙方实施顾问做需求调研 / 业务蓝图 / 流程确认
- 客户**无信息化经验**（不知道自己能要什么）
- 客户业务流程**尚未定型**（还在梳理中）
- 客户明确要求「以标准模板为基础 · 选择题式确认取舍」
- 有大量「多方案可选」的判定点

⚠️ **不适合**：客户已有成熟固定流程（照搬即可）／流程极简单无分支／客户明确拒绝被引导。

---

## 一、⭐ 核心理念

```
传统做法（客户视角改图）：
  我方画标准流程 → 客户看 → 客户提差异 → 我方改 → 再提 → 再改（3-5 轮）

本方法（我方预置 · 客户选择）：
  我方预置【全分支树】（覆盖所有可能）→ 会上客户【剪枝】→ 一轮定稿
```

### 三个底层判断

```
① 流程图本质 = 决策树
   每个判定点 = 一次分叉；把所有分叉展开 = 覆盖所有流程变体

② 客户"选"比客户"想"容易
   让人指出"缺什么"很难；让人回答"要不要"很容易
   → 选择题的认知负担远低于开放题

③ 我方的专业价值 = 帮客户看见他自己没想到的可能
   分支库越全 → 客户越信任 → 项目越顺
```

## 二、⭐ 四步法

### 第 1 步：建「分支库」（前期功课 · 最关键）

```
素材来源（四路合并）：
① 客户需求文档 —— 逐条读·提取"是否/可否/支持"类条款
② 客户产品与行业特性 —— 从产品推定（如无菌制剂→冷链/无菌传递）
③ 公司标准模板 —— 流程图模板里已有的判定点
④ 同行/同类项目范本 —— 其他同类项目的判定点

输出：一张《判定点清单》
  | 编号 | 判定点 | 选项 | 触发条件 | 我方建议 |
```

### 第 2 步：画「全分支树」

```
规则：
· 主干（默认推荐做法）→ 实线·深色
· 可选分支（待客户选）→ 橙虚线·细线
· 每个判定点标【树状编号】（如 1.3.a）
· 判定点旁挂【注释框】（选项说明 + 我方建议 + 勾选框）

布局：
· 主干走中间·分支往两侧延伸
· 同层节点对齐
· 每张图判定点控制在 5-8 个
```

### 第 3 步：会上「剪枝」

```
带着全分支图开会 → 逐点走：

客户说"这个不要"　→ ⛔ 剪掉（删除分支·或转灰）
客户说"这个要"　　→ ✅ 橙虚线 → 实线（升级为主干）
客户说"还有别的"　→ ➕ 补新分支
客户说"不确定"　　→ ⏳ 保留橙虚线·标注"待定·下次确认"

⭐ 关键动作：现场剪 · 当场改（投屏改图）
```

### 第 4 步：定稿

```
剪完枝 = 客户的实际流程
→ 图变干净（只剩主干 + 确认的分支）
→ 所有"待确认"消除（橙虚线归零）
→ 直接进蓝图/需求文档
```

## 三、⭐ 视觉体系（样式规范）

| 元素 | 样式 | 含义 |
|------|------|------|
| ⭐ 主干路径 | 实线 · 深色粗箭头 | 默认推荐做法（客户不动就走这条） |
| ⭐ 可选分支 | 橙虚线 · 细箭头 | 待客户确认的备选路径 |
| ⭐ 待确认节点 | 橙虚线框 + 斜体 | 尚未确认的环节 |
| ✅ 已确认节点 | 实线灰框 | 已明确（需求文档已写 / 客户已认） |
| ⛔ 不适用节点 | 灰色 / 直接删 | 已验证不需要 |
| 判定节点 | 菱形（三出口） | 一次分叉 = 一道选择题 |

### ⭐ 菱形三出口约定

```
       上角 = 入口（上游进来）
   左角 ─── 右角
       下角

⬇ 下角 = 【是】（主干路径·继续往下）
➡ 右角 = 【否】（旁路·报错/拒收/退回）
⬅ 左角 = 【其他】（第三分支·例外情况）

→ 好处：主干一眼可循·旁路和例外自然分流·不会挤在一侧
```

## 四、⭐⭐ 绘制五条铁律（图好看不好看，全在这五条）

> 实战踩坑后定稿——前 7 版都栽在这里

| # | 铁律 | 说明 |
|:-:|------|------|
| 1 | ⭐ **先定泳道，再排节点，最后连线** | 不要先连线再挪节点 |
| 2 | ⭐ **节点按【全局流程序号】定 y 坐标** | 不是"泳道内独立编号"——同泳道内自然有序，且相邻节点 y 接近 → 连线短 |
| 3 | ⭐ **锚点规则：菱形用左右 · 矩形用上下** | 菱形分支向两侧展开，不压下方节点 |
| 4 | ⭐⭐ **两段行走规则（防穿框的根本）** | ① 水平行走只在【全局行间隙】（该 y 在任何泳道都无节点）<br>② 垂直行走只在【泳道间走廊】（泳道之间的空白带，不越界） |
| 5 | ⭐ **待确认选项统一放图【最右侧】面板** | 按节点序号排列，每张卡标注"对应节点 N."；主图不散落注释框 |

**其他细节**

- 连线标签加**白色底色** → 避免与线/节点重叠看不清
- 同一泳道"跳过中间节点"的分支 → 绕本泳道**外侧走廊**走
- ⭐ 出图后跑**几何验证**（逐条线段与节点矩形求交）→ 确认"0 处穿框"再交付

## 五、⭐ 通用判定点分支库（示例：仓储/业务系统场景 · 可持续扩充）

| # | 判定点 | 选项 | 常出现在 | 触发条件 |
|:-:|--------|------|---------|---------|
| 1 | 是否委托加工 | 有 / 无 | 成品入库 | 数据不在本方系统 |
| 2 | 是否自动化（AGV/立库） | 有 / 无 | 入库·库内 | 仓库有自动化设备 |
| 3 | 是否称重 | 需 / 不需 | 收货 | 物料主数据「是否称重」= 是 |
| 4 | 是否记录温度 | 需 / 不需 | 收货 | 物料有温度要求 |
| 5 | 是否请验 | 需 / 不需 | 收货 | 物料主数据「是否线上请验」= 是 |
| 6 | 是否让步接收 | 支持 / 不支持 | 收货（外购） | 外购物料 + 不符标准 + 质量批准 |
| 7 | 是否绑定容器 | 需 / 不需 | 收货·上架 | 需要码垛的物料 |
| 8 | 是否有称量中心 | 有 / 无 | 领料出库 | 精细配比工艺 |
| 9 | 是否有销毁出库 | 有 / 无 | 出库 | 高价值/特殊管理物料 |
| 10 | 是否用追溯码 | 用 / 不用 | 成品入库·出库 | 成品序列化要求 |
| 11 | 系统是否对接 | 对接 / 手工 | 全局 | 上下游系统接口 |
| 12 | 是否需要审核环节 | 需 / 不需 | 入库·出库 | 合规留痕要求 |
| 13 | 是否有特殊储存 | 有 / 无 | 全库 | 冷链/阴凉/避光 |
| 14 | 是否散货/托盘 | 散货 / 托盘 | 上架·移位 | 包装形态 |
| 15 | 是否需下游复核接收 | 需 / 不需 | 领料出库 | 接收方确认流程 |
| 16 | 是否需人工收集数据 | 需 / 不需 | 收货 | 接口拿不到数据 |
| 17 | 是否有养护作业 | 有 / 无 | 库内 | 物料养护规则 |
| 18 | 是否需定期复验 | 需 / 不需 | 库内 | 物料有复验期 |

> ⭐ 用法：**把这张表当"检查清单"过一遍**——每一条都问自己"这个客户有没有这个分叉？"

## 六、⭐ 编号体系（树状 · 三处对应）

```
第 1 层：一级流程 → 1 收货管理 / 2 库内管理 / 3 发货管理
第 2 层：二级流程 → 1.1 采购收货 / 1.2 中间品收货 / 1.3 成品入库
第 3 层：判定点　 → 1.3.a / 1.3.b / 1.3.c（该流程图内的选择题）

⭐ 三处对应（可追溯）：
① 流程树总览图上的节点编号
② 流程图里的判定点编号
③ 选项清单/需求文档里的条目编号
→ 会上说"1.3.a"，三方都知道指的是什么
```

## 七、⭐ 图例模板（必须写在图顶部）

```
图例：⬇下角=是（主干）  ➡右角=否  ⬅左角=其他
      ｜ 实线=主干路径 ｜ 橙虚线=待客户确认（含 A/B 选项）
      ｜ ⭐编号=选择题编号（对应选项清单）
      ｜ ▭▭双层框=子流程
```

## 八、⚠️ 实施要点与坑

```
① ⭐ 分支库要"全" —— 客户想不到的你也列上（这才是专业价值）
② ⭐ 每张图判定点 5-8 个 —— 超过 10 个图会乱·客户会烦
③ ⭐ 主干要"敢推荐" —— 不能只列选项不给建议（客户要的是引导）
④ ⚠️ 别把"很可能不要"的分支也画上 —— 会显得不专业（要基于事实推断）
⑤ ⚠️ 待确认分支必须标注"待确认" —— 不能混在主干里（否则定稿后扯皮）
⑥ ⭐ 会上要"现场改图" —— 客户看你说完就改·信任感最强
⑦ ⭐ 剪枝后要留痕 —— 删掉的分支在会议纪要里记一句"客户确认不需要 XX"
   （防止后期客户反悔说"当时怎么没做"）
⑧ ⚠️ 推断必须标注 —— 分支库里的"产品推断项"要写明依据·不能当事实
⑨ ⚠️ 判定节点 ≠ 所有分叉 —— 动作相同的"参数/规则选择"写注释；
   动作不同的"走法分叉"才用菱形（滥用菱形会让图爆炸）
```

## 九、📊 与传统做法的对比

| 维度 | 传统做法 | ⭐ 全分支法 |
|------|---------|-----------|
| 起点 | 一条标准流程 | 全分支树（覆盖所有可能） |
| 会上动作 | 客户提差异 | 客户做选择题 |
| 认知负担 | 高（要"想出来"） | 低（只要"判断"） |
| 改图轮次 | 3-5 轮 | 1 轮剪枝 |
| 客户感受 | 被动接受 | 主动选择（有掌控感） |
| 我方形象 | 记录员 | ⭐ 领域专家 |
| 风险 | 漏需求（客户没说·我方没想到） | 分支过多致图乱（可控） |

## 十、🔗 与其他方法的衔接

```
需求调研四维记录法（research-4d-method）
  差异 GAP    → 本方法的「可选分支」
  待确认 OPEN → 本方法的「待确认菱形」

会议纪要写法（research-meeting-minutes）
  剪枝结果 → 记入纪要的「决议事项」
  删除的分支 → 记一句"客户确认不需要 XX"（留痕）

闭环：调研记录 → 全分支图 → 会上剪枝 → 纪要留痕 → 定稿
```

---

## 十一、⭐ 一句话总结

```
先替客户想全，再让客户挑。
—— 把"需求调研"从"问答"变成"选择"，
   把"流程图"从"一条线"变成"一棵树"，
   把"改图 5 轮"变成"会上剪枝 1 轮"。
```
