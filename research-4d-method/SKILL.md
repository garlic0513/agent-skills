## 一、四个维度

| 维度 | 英文 | 记录什么 | 现场问法 | ⭐ 记录要点 |
|:----:|:----:|---------|---------|-----------|
| 现状 | AS-IS | 客户目前怎样开展工作 | "这个业务现在是怎么做的？" | 走一遍实际动作；⭐ 重点记**手工动作**和**纸质单据**（这是最容易漏的痛点来源） |
| 目标 | TO-BE | 客户希望新系统实现什么 | "上了系统后你希望变成什么样？" | 记**原话** + 背后诉求（合规？省人？防错？追溯？） |
| 差异 | GAP | 现有标准能力能否满足目标 | "标准产品有没有？要不要改？" | ⭐ 三选一：`能（标准）` / `部分（需配置）` / `不能（需定制）` |
| 待确认 | OPEN | 哪些问题没定、谁确认 | "这条谁定？什么时候给答复？" | ⭐ 必须带**责任人 + 期限 + 影响** |

### 为什么顺序不能颠倒

```
现状 AS-IS → 目标 TO-BE → 差异 GAP → 待确认 OPEN

· 没有"现状"就谈"目标" → 客户讲理想，落不了地
· 没有"目标"就谈"差异" → 变成推销标准产品，客户反感
· 没有"差异"就谈"待确认" → 清单全是废话，没有决策点
```

## 二、⚠️ 每个维度的追问清单（现场照着问）

### AS-IS 现状（问出真实操作）

```
□ 这件事现在是谁做的？几步？
□ 用什么工具？（纸质 / Excel / 旧系统 / 口头）
□ 一次要多久？一天多少次？
□ 出错会怎样？谁兜底？
□ 有哪些单据/表单？长什么样？
⭐ 追问："能不能给我看一下现在用的表？"
```

### TO-BE 目标（问出真实诉求）

```
□ 上了系统后，你希望第一步变成什么？
□ 最想解决的是哪个痛点？（排前三）
□ 变化后谁的工作量会减少/增加？
□ 有没有硬性要求？（法规/审计/客户要求/总部要求）
⭐ 追问："如果只能实现一个，你先要哪个？"
```

### GAP 差异（问出方案边界）

```
□ 标准产品有现成的吗？（能）→ 直接演示
□ 差不多但要调？（部分）→ 记清调什么、能不能配置
□ 完全没有？（不能）→ 记为定制需求，标工作量
⭐ 追问："如果标准产品不是这样，而是那样，能接受吗？"
```

### OPEN 待确认（问出决策人）

```
□ 这条谁来定？（业务？QA？IT？老板？）
□ 什么时候能给答复？
□ 拖着不定会卡住什么？（说清影响才有推动力）
⭐ 追问："那我先按 A 方案写，你确认后我再改，可以吗？"
```

## 三、记录表模板

| 编号 | 维度 | 业务/问题 | 内容（客户怎么说 / 我方怎么答） | 依据 | 责任方 | 期限 | 状态 |
|:----:|:----:|----------|------------------------------|------|:------:|:----:|:----:|
| 1.1 | 现状 | | | | | | 已记录 |
| 1.2 | 目标 | | | | | | 已记录 |
| 1.3 | 差异 | | | | | | 待评估 |
| 1.4 | 待确认 | | | | | | ⏳待答 |

**写法约定**

```
· 维度列：只写 现状/目标/差异/待确认 四个值
· 差异列的内容必须以 能（标准）/ 部分（需配置）/ 不能（需定制） 开头
· 待确认列必须填责任方 + 期限，否则不许进表
· 客户原话用引号原样引用（"我们要一物一码"）
· 推断必须标"推断"+依据，不得写成事实
```

## 四、⭐ 输出物：三张清单

```
① 需求清单  = 目标 TO-BE + 差异 GAP（能/需配置/需定制）
   用途：进蓝图/需求规格说明书；⭐ 是报价与工期的依据

② 选项清单  = 差异 GAP 中"需客户决策"的项 → 做成 A/B 选择题
   用途：给客户勾选，避免开放式讨论

③ 风险清单  = 待确认 OPEN 项（带责任人+期限）
   用途：每日/每周跟踪，防止悬空
```

## 五、与流程图方法衔接（闭环）

```
调研四维记录法            全分支流程图工作法
  AS-IS 现状  →  流程图"主干"（客户实际走法）
  TO-BE 目标  →  流程图"推荐路径"（我方建议做法）
  GAP  差异   →  流程图"可选分支 / 需定制点"
  OPEN 待确认 →  流程图【待确认菱形】+ 右侧选项面板

闭环：调研四维 → 流程图分支 → 会上剪枝（客户勾选）→ 定稿
⭐ 会后先更新 4D 表，再改流程图 —— 顺序反了会漏
```

## 六、💊 GMP / CSV 场景的额外要求

```
① 每条差异/需求都挂 URS 条款号 → 形成"需求↔设计↔测试"追溯链
   （CSV 验证的核心证据链）
② 涉及合规判断的条目写"待 QA 确认"，不自行判定
③ 检验/放行/状态类需求要问清"数据从哪来、谁录入、谁审核"
   （客户无 LIMS 时尤其关键 → 人工传递的断点就是最大风险点）
④ 变更要留痕并同步进变更台账
⑤ 服务法规：21 CFR Part 11 / EU Annex 11 / GAMP 5 / ALCOA+
```

## 七、常见错误

| 陷阱 | 后果 | 正解 |
|------|------|------|
| 只记"目标"不记"现状" | 方案脱离客户实际，上线即返工 | ⭐ 先问清现在怎么干 |
| GAP 不写"标准/配置/定制" | 报价工期没依据 | ⭐ 三选一必填 |
| OPEN 不带责任人和期限 | 永远悬空，最后变扯皮 | ⭐ 当场问出来 |
| 客户原话改写成"专业表述" | 丢了关键信息，事后扯皮 | ⭐ 原话加引号保留 |
| 把推断当事实 | 交付物被追责 | 标"推断"+依据 |
| 一次调研想覆盖全部业务 | 记不全、客户烦 | ⭐ 每次 1~3 个议题，分批推进 |
| 会后不更新流程图 | 4D 表与流程图脱节 | ⭐ 当天同步更新 |

## 八、自查清单（每次调研后过一遍）

```
□ 每个业务点都有 AS-IS 吗？
□ 每个 AS-IS 都配了 TO-BE 吗？
□ GAP 都写了"能/部分/不能"吗？
□ OPEN 都有责任方 + 期限吗？
□ 客户原话引了吗？
□ 涉及合规的条目引 URS 条款了吗？
□ 三张清单（需求/选项/风险）产出了吗？
□ 流程图同步更新了吗？
```

## 九、实战示例（制药 WMS 项目）

| 编号 | 维度 | 业务/问题 | 内容 | 责任方 | 状态 |
|:----:|:----:|----------|------|:------:|:----:|
| 2.1 | 现状 | 收货单证来源 | 客户无 ERP 接口，单据全部手工录入 | 客户 | ✅已确认 |
| 2.2 | 目标 | 单据追溯 | 希望系统内完整追溯，满足 FDA/cGMP | 客户 | ✅已确认 |
| 2.3 | 差异 | 接口对接 | 部分（需配置）：标准产品可做接口，但客户四系统未打通→改手工模式 | 我方 | ✅已确认 |
| 2.4 | 待确认 | 让步收货 | 是否启用？（URS 未列明） | 客户 QA | ⏳待答 |
| 2.5 | 待确认 | 库存状态默认值 | 收货后默认"待检"或"合格"？ | 客户 QA | ⏳待答 |

> ⭐ 这张表本身就是"待确认选项清单"的底稿 —— 会上按它逐条过。
