**写法约定**

```
· 维度：只写 现状 / 目标 / 差异 / 待确认
· 差异必须以  能（标准）/ 部分（需配置）/ 不能（需定制）  开头
· 待确认必须填 责任方 + 期限（否则不许进表）
· 客户原话用引号原样引用
· 推断标"推断"+依据，不得写成事实
```

## 现场追问清单（照着问）

### AS-IS 现状

```
□ 谁做的？几步？
□ 用什么工具？（纸质 / Excel / 旧系统 / 口头）
□ 一次多久？一天多少次？
□ 出错会怎样？谁兜底？
□ 有哪些单据/表单？⭐ "能不能给我看一下现在用的表？"
```

### TO-BE 目标

```
□ 上了系统后第一步变成什么？
□ 最想解决的前三个痛点？
□ 谁的工作量会减少/增加？
□ 有硬性要求吗？（法规/审计/客户/总部）
⭐ "如果只能实现一个，你先要哪个？"
```

### GAP 差异

```
□ 标准产品有现成的吗？（能）
□ 差不多但要调？（部分）→ 记清调什么、能否配置
□ 完全没有？（不能）→ 记定制需求 + 工作量
⭐ "如果标准产品是另一种做法，能接受吗？"
```

### OPEN 待确认

```
□ 这条谁定？（业务 / QA / IT / 老板）
□ 什么时候给答复？
□ 拖着不定会卡住什么？（说清影响才有推动力）
⭐ "我先按 A 方案写，你确认后我再改，可以吗？"
```
