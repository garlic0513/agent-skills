# 认知框架法（Cognition Framework Method）· 完整版

> **核心洞察（2026-08-22）**：**在提出疑惑之前，要表达疑惑；在表达疑惑之前，要觉察疑惑。**
> 新手面对陌生系统的真正瓶颈，不是"问不好"，而是"不知道自己不知道什么"——没有认知框架，就没有参照物，疑惑不会浮现。
> **完整版双引擎**：觉察疑惑 = 觉察已知（连环拷问挖掘）＋ 觉察未知（框架对照）——两条腿走路。

## 理论支撑（认知科学/学习科学）

| 理论 | 提出者 | 与本方法的关系 |
|------|--------|---------------|
| **元认知（Metacognition）** | Flavell | 对「自己知道/不知道什么」的监控——新手元认知监控弱，方法训练它 |
| **达克效应（Dunning-Kruger）** | Kruger & Dunning | 能力不足者高估自己——「不知道自己不知道」的正式名称 |
| **未知的未知（Unknown unknowns）** | Rumsfeld | 无法提问的区域——框架把它们转化为「已知的未知」（可问） |
| **先行组织者（Advance Organizer）** | Ausubel | 学细节前先给框架——**认知框架卡的直接理论基础** |
| **图式（Schema）与认知冲突** | Piaget | 新信息与既有图式对比→冲突→疑惑→学习动机 |
| **认知脚手架（Scaffolding）** | Vygotsky（ZPD） | 框架是脚手架——让新手够到最近发展区 |
| **生产性困惑（Productive Confusion）** | D'Mello & Graesser | 适度困惑促进深层学习——疑惑是学习起点不是障碍 |
| **问题驱动学习（PBL）** | Barrows | 好问题=学习引擎——方法保证问题能被提出 |
| **苏格拉底式提问（Socratic）** | 苏格拉底 | 连环追问让对方自己发现矛盾与盲区——拷问机制的理论源头 |

## 双引擎模型（连环拷问 × 认知框架）

```
觉察已知（连环拷问）         觉察未知（认知框架对照）
「我知道什么/我以为我知道」        「我不知道什么/该知道什么」
连环提问挖掘（目标/背景/边界）    先行组织者（系统应该有什么）
→ 理清已有想法                     → 浮现知识盲区
        ↓ 合并 ↓
  完整认知地图（知道+不知道）→ 精准提问/求助/行动
```

## 核心流程（5 步）

```
① 拷问分层 ② 建框架（先行组织者） ③ 对照实际（5问） ④ 有效求助 ⑤ 元认知升级
```

### 第 1 步：拷问分层（连环拷问机制——挖掘已知）
任务开始时（模糊/复杂任务自动启用），连环拷问 8-15 个尖锐问题，按主题分组：
- **目标**：到底要产出什么？给谁看？验收标准？
- **背景/动机**：为什么现在做？之前试过什么？卡在哪？
- **范围与边界**：明确不做哪些？哪些可砍？
- **约束**：时间/格式/平台/风格/技术限制？
- **偏好**：参考样例？喜欢什么风格？忌讳什么？
- **风险点**：最容易翻车的地方？

**拷问产出**：三层清单——「我知道」「我以为我知道（需验证）」「我不知道」——回答不上来的问题 = 疑惑点（进入第 2-3 步处理）。

> 规则：答不上来/回答矛盾 → 立即追问；用户说「别问了直接做」→ 停止并标注假设。

### 第 2 步：建框架（先行组织者）
- 对「我不知道」区域：让 AI 讲「这个系统/领域**应该有什么**」（关键要素、典型关系、核心指标）
- 产出**认知框架卡**（模板见下）：是什么/核心构成/关系与连接/状态判断/观察清单/5问清单/边界与禁忌
- **先地图后找路**——带着预期清单去，差异才会冒出来

### 第 3 步：对照实际（5 问触发清单）
对每个对象/模块问 5 个问题（答不上来的=疑惑点）：
```
① 这是什么？        （不认识 → 记录 → 问）
② 它和什么相连？    （从哪里来、到哪里去 → 跟路径走）
③ 为什么这么接？    （和典型布局比 → 差异 = 疑惑）
④ 显示什么？        （指示/数值 → 什么含义、多少正常）
⑤ 能操作什么？      （操作项/权限 → 边界）
```

### 第 4 步：有效求助（表达疑惑）
- **拍照 + 标注**（手机拍、图上写字——标出关键部分——不用画得好，能看懂就行）
- **一句话说明结构**（「它是怎么和周围连起来的」）
- 发给 AI → 视觉识别 + 生成示意图 → 双方对齐（AI 不了解具体情境——用户纠偏）
- 形成**共识图**存档 → 以后所有问题基于图问答（准确率大幅提升）

### 第 5 步：元认知升级
- 每完成一轮：框架卡更新（发现的新要素/新关系补进去）
- 自我监控增强：「我现在能说出 3 个不懂的地方了」（达克效应消退）
- 熟悉后：框架卡降级为速查卡（新领域重复 1-5 步）

## 认知框架卡模板（通用版——适配多领域）

```markdown
---
type: cognition-framework
usage: 任何陌生领域认知——「应该看什么/该疑惑什么」
---
# XX 认知框架卡（通用版）
## 它是什么（一句话类比）
## 核心构成（由什么组成——部件/模块/要素/步骤）
## 关系与连接（各部分怎么关联——连接/接口/关系/流转）
## 状态判断（正常长什么样——表读数/日志指标/应用表现）
## 观察清单（我该看什么——识别点）
## 5 问疑惑清单（通用：①这是什么 ②由什么构成 ③怎么连接 ④正常什么样 ⑤我能动什么）
## 边界与禁忌（红线/禁区/常见坑）
```

**领域映射**：设备→（构成=部件/连接=物理连接/状态=表读数）；软件→（模块/接口/日志指标）；概念→（要素/关系/应用表现）；业务→（步骤/流转/节点指标）。详细映射见 `templates/cognition-framework-card.md`。

## 应用场景

| 场景 | 用法 |
|------|------|
| 陌生领域接触 | 第①步拷问分层 → 第②③步框架+5问 → 记录求助 |
| 模糊任务开工前 | 第①步拷问（目标/边界/风格）→ 挖清需求再开工 |
| 学习新领域（AI/验证/任何） | 第①步「我知道/不知道」分层 → 第②步建框架 → 对照阅读 |
| 求助 AI 前 | 先回答 5 问模板（能答几条）→ 说不清的部分 = 真正要问的 |
| 教学/带新人 | 拷问分层 + 框架卡带人入门（对方自己发现疑惑） |

## 关键要点（pitfalls）

- **先觉察后行动**：跳过拷问/框架直接做 = 回到「不知道问什么/做什么」的老路
- **拷问不是审问**：语气轻快友好；答不上来正是价值（疑惑点采集）
- **AI 可以生成框架**（「该看什么」）但不能代替实际验证（AI 不了解具体情境——用户纠偏）
- **框架卡要迭代**：不是一次性文档——每次实践后补充（新要素/新发现）
