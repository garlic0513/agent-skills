# 流程说明（4.x.3）怎么写：图与说明是一对

> 从 SKILL.md 下沉（2026-10-28 瘦身重构）。

📄 **模板规格 + 仿写参考 + 按图捋检查清单：`references/process-description-template.md`**



用户会先要求画图，再要求「**捋一下流程说明**」或「**参考这段内容作为模板进行仿写**」——

图和说明是**同一交付物的两半**，编号必须互相对得上。不要只交图。



⭐⭐ **读说明的人不懂药企 → 节点文案必须用通用表述**（2026-10-26 用户原话：

*"目前我们项目上的同事还是不大理解药企里面复核的定义，所以流程说明里的节点要用通用一点的表述"*）：



```

· 复核 → 第二人核对（由非录入人确认）          放行 → 批准使用

· 待检 → 暂不可用（等检验结果）                让步收货 → 带条件接收

· 审计追踪 → 系统保留操作记录                  请验 → 提交检验申请

· ⭐「处理逻辑」列 ≤25 字：只写"做什么 + 判什么"，超了就是写多了

  ✅ 第二人核对数量、码、托盘是否一致，一致通过

  ❌ 由复核人对数量、监管码、托层级进行核对，一致则通过，不一致则退回并注明错误类型…

· 一行动作做两件事 = 拆两行，别用逗号堆在一格

```

### ① 先抠出"模板风格 7 条"再仿写（别自己发明格式）



用户给一段现成说明当模板时，先提炼风格再动手：



```

① 主步骤 = 「1.」「2.」「3.」平铺，不缩进

② 子步骤用点号逐级展开：6.1 / 8.1.1 / 8.1.1.1（层级靠"点"不靠缩进）

③ ⭐ 判定节点写法固定：`X.1 不符合…，执行序号7拒收货物` / `X.2 符合…，继续执行序号11`

   （判定分支的两边都必须写"下一步去哪"）

④ 字段/界面项清单用 ①②③ 罗列

⑤ 界面按钮单独起行：`【收货确认】按钮逻辑` + 逐条规则（待收>0 清空数量可继续 / 待收=0 跳回列表…）

⑥ 结尾固定一句「…，流程结束」

⑦ 编号体系与图完全一致：图上"8.1.1 校验供应商" → 说明里就是 8.1.1

```



### ② ⭐ 按图捋说明的检查法（产出"待理顺清单"）



用户会说「**根据这个图写个流程说明**」——不能只抄节点文字，要逐节点查 4 件事：



```

□ ① 图上有、说明里缺（漏步骤）

□ ② ⭐ 判定分支的【一边没写后续】：菱形两条边，常常只写了"是"的去向，"否"没说去哪

□ ③ ⭐ 终止型节点【没有去向】：拒收 / 报错 / 拒收退回 这类框在图上是"死头"，

     说明里必须给归宿（"后续供应商重新送货到仓库或关闭ASN单"），否则等于没闭环

□ ④ 图上"并行"还是"串行"没说清：同一节点横向+纵向各引一条线时，

     说明要明确是【并行两条路径】还是【先后两条路径】（本次序号11 就踩这个）

```



**回话格式**：说明正文 + 一张 `⚠️ 按图捋出的 N 处待理顺` 表（位置/问题/建议），

让用户拿这张表去补图或拍板 —— 比只交一段文字有用得多。



### ③ 仿写时必做的三处"去模板化"



```

① 删【不适用】的步骤：模板带 AGV/WCS/立库 而客户没有 → 整段删，别留着

   （删完补一句"未删除会显得不专业"不如直接删干净）

② 去品牌/客户名残留：模板里"XX 公司 WMS-WEB""货主是否为 XX" → 换成本客户口径

③ ⭐ 可疑项【就地标 ⚠️ 待确认】，不要臆断：

   库存状态默认值（待检/合格）、批号用谁的、要不要请验、接口是否打通

   → 写成"⚠️ 待确认（A…／B…，建议…）"，会上一次性问掉

```



### ④ 内容概述（4.x.1）三件套



```

业务范围：本流程包含哪些业务、单据类型有哪些

涉及系统：ERP / WMS-WEB / WMS-RF / …（有接口就写，没有就写"手工"）

⭐ 不适用说明：该客户没有的设备/系统，明确写一句"已删除 AGV/WCS 相关步骤"

```
