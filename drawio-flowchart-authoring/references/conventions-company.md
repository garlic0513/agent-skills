### ① 顶部图名（必修）
格式 **「一级流程-二级流程流程图」**，例：`收货管理-采购成品入库流程图`、`收货管理-退料入库流程图`。

⚠️ 加了标题后**泳道/节点 y 坐标整体下移 80**，否则压在一起。

### ② ⭐ 菱形三出口（用户明确指定）
判定节点**用三个角做出口**，别只用两条边：

```
上角 = 入口（上游进来）
⬇ 下角 = 【是】（主路径·继续往下）      exitX=0.5 exitY=1
➡ 右角 = 【否】（旁路·报错/拒收）        exitX=1   exitY=0.5
⬅ 左角 = 【其他】（第三分支·例外情况）    exitX=0   exitY=0.5
```

⭐ 好处：客户一眼看出主路径（沿下角一路到底）；旁路/例外自然分流到两侧，不与主线打架。
⭐ 自查：同一判定节点的两条边**不能都走同一个角**（本次踩过：是/否都用了右角 → 重叠）。

### ③ 条件分支必须标"触发条件"
用户要求："这种类似的分支项可以都加进流程图，但是需要做个条件标记，比如满足什么条件后才需要这个分支"。

```
· 节点内标注：   ⭐条件：委托加工成品
· 连线上标注：   ──「否（自制）」──▶  ──「是（委托加工）」──▶
· 规则说明区：   非"走哪条路"而是"系统怎么判断"的，写节点下方说明
                 （例：入厂批号 → 根据批号生成规则赋值）
```

### ④ ⭐ "待客户确认"标记 + 样式区分
需要客户拍板的选项点，**不要自己拍板**，画进图但用样式区分：

```
· 实线灰框 = ✅ 已确认（URS 明确 / 无争议）
· ⭐虚线橙框 = ⚠️ 待客户确认  (dashed=1；fillColor=#ffe6cc;strokeColor=#d79b00;fontStyle=2)
· 菱形     = 判定节点
```

### ⑤ ⭐ 用词校对（交付前必跑）

用户会逐字看图并纠正错字（本次：**「效验」→「校验」**，正确写法是**校验**）。
麻烦的是**错字常常来自公司/他人范本**（某药企范本原文就写「效验扫描监管码数据」），照抄就传染。

```python
# 交付前全量扫（含多页 mxfile 的每一页）
for wrong, right in [('效验','校验'), ('登计','登记'), ('批次号号','批次号'), ('销毁消','销毁')]:
    if wrong in open('x.drawio', encoding='utf-8').read():
        print('⚠️ 应为', right)
# 修完再验残留 = 0
```

⭐ 同理适用于**设备名 / 系统名 / 客户名 / 货主名**：抄来的模板会把上个客户的东西带进来 ——
见 §八 关键词计数法 与 `references/scope-change-and-gap-audit.md`。**凡是"抄来的"，交付前都要过一遍**。

本次实测（蓝图文档里的残留，画图时也会跟着抄进来）：
```
· "涉及系统"字段写着「**某药企**WMS-WEB / **某药企**WMS-RF」→ 应删客户前缀
· 入厂批号规则写着「按 ASN 单货主是否为**某药企**，使用两套规则」→ 换成客户自己的规则
· 货主代号列举「广东嘉博 / 上海宣泰 / 某药企生物医药」→ 客户是自有单货主，整段要改
· 表标题「**某药企**WMS系统与其它系统对接接口清单」+ 整表 21 个别家接口 → 最尴尬的一处
```

### ⑥ ⭐⭐ 「判定节点 ≠ 所有分叉」+ 重叠双查（用户会直接说\"图中重叠，我看不清楚\"）

**原则：不同选项的【处理动作】是否一样？**

```
· 一样（只是参数/规则不同）→ ❌ 不要画菱形，写进该环节节点的注释
   例：「退回哪个库位」（原库位/退料区/待检区）—— 三种都只是\"上架到指定库位\"，
       动作相同 → 应写在上架流程节点下方：\"⭐1.4.c 按规则分配库位：A/B/C\"
· 不一样（走法/环节不同）→ ✅ 用菱形分叉
   例：「是否符合退料条件」（继续收货 vs 拒收+异常记录）
```

⚠️ 把参数类判断硬画成菱形 → 多条出边必然汇到同一个下游节点 → 视觉重叠，客户看不清。

**交付前重叠自查（两查，都要跑）：**

```python
import re
from collections import defaultdict
x = open('x.drawio', encoding='utf-8').read()
seen = defaultdict(list)
for m in re.finditer(r'value="([^"]*)" style="[^"]*exitX=([\d.]+);exitY=([\d.]+)[^"]*"'
                     r' edge="1"[^>]*source="(\w+)" target="(\w+)"', x):
    lbl, ex, ey, s, t = m.groups()
    seen[(s, ex, ey)].append(t)          # 查①：同一源节点的同一出口角指向多个目标？
for k, v in seen.items():
    if len(v) > 1 and len(set(v)) > 1:
        print('⚠️ 重叠:', k, '→', v)
# 查②：多条边指向同一节点、且源节点在同一侧 → 也易压线（参数类判断的典型症状）
```

本次实测踩到两处：① 1.4.c 三条选项两两汇到同一个\"按指定库位分配\"节点 → 改成注释；
② `r3 → d3` 与 `r3 → w4` 都走左角 → 后者是**多余连线**（免检路径本来就经 l3 → w4），删掉。

⭐ 回话时给用户\"逻辑链\"而不是只说\"改好了\"：
把修改前后每条线的 `源 ──[标签](出口角)──▶ 目标` 列出来，他一眼能核对。

### ⑧ ⭐⭐ 某个功能"该不该画成节点"——四步判据（以「让步收货」为例）

用户会指着图问：*"关于让步收货这个选项，是否要安排节点？"* 别凭业务感觉答，走这四步：

```
第 1 步 · ⭐ 先数它在【需求文档】里出现几次（最容易忽略·价值最高）
   grep 该关键词在 URS / 蓝图 里的出现次数：
   · 本次实测：URS 里「让步」= 0 次，蓝图里 = 5 处
   → ⭐ 0 次 ⇒ 这是【抄来的范本功能】，不是客户需求
     ⇒ 必须做成【选择题】问客户是否启用，**不要默认画进图**
   （范本残留的另几种形态见 §十 ⑤：设备/系统名前缀、货主代号、接口清单整表）

第 2 步 · 按【动作是否一样】分三种形态（§十 ⑥ 的推广）
   | 出现形态 | 字段 or 分支 | 处理 |
   | 初检登记项「是否让步收货」（勾选） | 字段 | ❌ 不画菱形 → 写进该环节节点正文 |
   | RF 端【收货确认】/【让步收货确认】按钮 | 同一节点的两个按钮 | ❌ 不画 → 在节点上加注按钮名 |
   | PC 端【让步收货审批】（审批状态/审核人/审批文件） | ⭐ 真分支 | ✅ 画菱形 + 节点 |

第 3 步 · ⭐ 插入位置看【触发规则依赖什么】
   本次依据蓝图原文："让步收货且审批状态=待审批/不通过 → 系统【锁定库存】；
   审批通过 → 【解锁库存】"
   → 锁/解锁的前提是【库存已生成】
   ⇒ ⭐ 分支必须插在「更新收货记录+库存」之后、「上传资料/打印标签」之前，
     而不是按业务感觉放在"初检阶段"（那里只是勾字段）
   ⭐ 通用判据：动作的触发条件引用了某个前置产出（库存/批号/放行状态）
     → 该分支就挂到那个前置节点之后，别提前。

第 4 步 · ⭐ 新分支的【操作角色】有没有对应泳道？
   让步审批是 QA 做的 → 而原图 6 条泳道里没有 QA
   ⇒ 要新增泳道「质量保证部（QA）」（后续 4.9 质检放行也在这条泳道·提前建好）
   ⚠️ 加泳道 = 全图宽度/节点 x 重算 → 一次性规划好，别加完又改
```

⭐ 回话模板（用户要的是可决策的答案，不是"可以加"）：
```
① 事实：URS 0 次 / 蓝图 5 处（来自 XX 范本）
② 判断：分三种形态，只有「XX 审批」该画（理由：动作不同 + 影响库存可用性）
③ 位置：插在节点 N 之后（理由：锁库存的前提是库存已生成）
④ 建议：右侧面板加一张选择题卡「是否启用 XX？（A 启用 / B 不启用）」
⑤ 追问：按 A 画还是先只挂选择题卡？
```

### ⑨ ⭐⭐ 「复核」要不要画成节点 —— 用控制层级判，别一有风险就加框

用户会问：*"哪些环节需要复核？能不能用风险分析那套标准判断？公共收货子流程要不要加复核，还是用更高控制层级？"*

⭐ 核心认知：**风险分析的输出是「需要什么强度的控制」，复核只是五种控制之一，且强度中等。**

```
控制层级（从上到下效果递减·借安全工程的 Hierarchy of Controls）
① 消除   → 让动作不存在（扫码带出数据，不用手录）        ★最强
② 防错   → 系统拦住错（查重/容差/状态匹配/必填）          ★强
③ 权限分离 → 谁都不能独自完成（状态变更只有 QA 能改）      ★强
④ 人工复核 → 第二双眼睛（检出率约 70–90%，会疲劳）        ●中
⑤ 事后检测 → 抽检/对账（发现晚，属检测不属预防）           ○弱
```

**五步判据（画图时按顺序走，卡在第一步就停）：**

```
① 能让这个动作不存在吗？      → 能 = 消除（节点保留，标注"由系统带出·不可编辑"）
② 系统能拦住错吗？            → 能 = 防错（画【蓝色判定菱形】，右上角标系统）
③ 能不给这个人这个权限吗？    → 能 = 权限分离（不加节点，写在节点备注/处理逻辑列）
④ 都不行 → 才画【复核】方框     （此时才值得占一个节点）
⑤ 连复核也做不到（单岗作业）？ → 事后抽检 + 提高抽样 + 在验证方案里写明理由
```

**风险打分只用来决定"要不要走到第 ④ 步"**：`RPN = S(严重性) × P(发生概率) × D(可检测性，分越高越难发现)`
- `S 高 + D 差`（如手工录入批次/数量、盘盈亏过账）→ 必须叠加 ②③④，复核不能是唯一屏障
- `S 高 + P 低`（如待检转合格）→ 用 ③ 权限分离即可，**不画复核**（更强且省人）
- `S 中 + P 高` → 优先 ②，复核降级为抽检

**流程图上的表达（不加框也能看出控制强度）：**

```
图例扩展（评审时说明一句，不算偏离模板）：
  SYS  系统防错      SEP  权限分离      2P  双人复核      DET  事后检测
→ 标在节点右上角小字，比给每个动作加一个"复核"方框省地方、也不掩盖真正的风险点
```

⚠️ 三个反模式：**① 图上一堆"复核"框**（评审看不出薄弱点在哪，且单岗客户根本执行不了）／
**② 把复核当唯一屏障**（同账号自签即失效）／**③ 公共子流程统一加复核**（扫箱/扫托本来靠码带数据，
给它们加复核＝让人再确认机器读对的数据，纯浪费）。

⭐ 实测应用（收货子流程 4 条路径）：扫托/扫箱 = ①消除 + ②防错；收货确认 = ③权限分离；
只有【按单收货的数量录入】是唯一"人读人录"，才考虑 ④，且客户单岗时用 ②（箱规自动算 + 范围校验）+ ⑤（周抽检）替代。

⭐ 流程说明里补一段「控制方式说明」（4 行：消除/防错/权限/复核），比多画一个复核框更有说服力——
评审看到的是"风险已被更高级控制覆盖"，而不是"人盯人"。

### ⑦ ⭐⭐ 待确认选项统一放【图最右侧独立面板】· 按节点序号排列

用户原话：*\"橙色判断框统一移到最右侧按节点序号排列\"*。

早期做法是把选项注释框**挂在对应节点正下方** —— 用户否掉了：散落后主图很乱，且会上没法逐条过。

```
图面布局：
┌───────────────────────────┬──────────────────────────┐
│  主图（泳道 + 节点 + 连线）  │ ⭐ 待客户确认选项（按节点序号）  │
│                            │  1️⃣【对应节点 5.】… ☐A ☐B    │
│                            │  2️⃣【对应节点 8.1】…          │
└───────────────────────────┴──────────────────────────┘

· 面板标题条（橙底 #F4B183 / 橙框 #C55A11 / 深橙字）
· 卡片 = 橙虚线圆角框（#fffdf5 / #d79b00 dashed），文本前缀【N】= 序号
· ⭐ 卡片按【节点序号】排序，且卡内首行写「【对应节点 N.】」→ 能在主图里找到落点
· 面板宽度默认 560；pageWidth = 主图右边界 + 40 + 面板宽 + 40
· pageHeight 取 max(主图高, 面板所需高)  ← 面板比主图高时别被裁掉
· 适用对象：所有 confirm/optbranch 类\"待客户拍板\"的点（选项 A/B/C + 我方建议 + 客户确认☐）
· 两类内容都进面板：① 待确认判定点（选择题）② 说明/风险类批注（如\"ERP 不打通→手工建单\"）
```

⭐ 会上用法：左侧看流程 → 右侧逐条过卡片（\"1️⃣ 这个点咱们是怎么做的？\"）→ 客户圈选 → 回图改样式。

⭐ 已固化进 `scripts/drawio_swimlane.py`：spec 加 `"notes": [{"node": "b2", "text": "…"}]` 即自动生成面板 + 序号；
自查⑦会核对\"卡片数 == notes 数\"且\"面板标题存在\"。
