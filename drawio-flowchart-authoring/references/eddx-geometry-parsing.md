# 解析 .eddx 几何（读懂用户/客户发来的亿图草稿）

> 为什么值得做：只提文字 → 读不出「泳道是横是竖 / 每条带多高 / 流程怎么绕圈」，
> 而这些正是「该照抄什么」的关键。本次只提文字，我按垂直泳道重画，被连否 8 版；
> 解析几何后发现 **用户自己的版本是横向泳道带** —— 方向从一开始就猜错了。

## 一、包结构

```
xxx.eddx（= ZIP，可直接 unzip）
├── pages/page1.xml      ← 全部图形（本文件 ~1.6MB）
├── document.xml         ← 文档级设置
├── theme.xml / templates.xml
├── rels/page1_rels.xml  ← 引用关系
└── thumbnail.jpeg       ← 缩略图（分辨率极低，只能看轮廓）
```

## 二、元素模型（ET 解析要点）

```
⚠️ 元素常带命名空间前缀 → 解析前先去前缀 / xmlns，否则遍历不到：
   x = re.sub(r'\sxmlns(:\w+)?="[^"]*"', '', raw)
   遍历时统一用 tag.split('}')[-1] 取本地名

Shape 的 Type 属性决定它是什么：
   SwimLane   = 泳道
   Shape      = 普通节点（也含泳道的边框装饰形状）
   ConnectLine= 连线
   Group      = 组合（Edraw 常把 形状+文字域 放一个 Group 里）
   GuideLine  = 参考线

几何在 <Transform> 里：
   Width / Height            尺寸
   Angle                     旋转角（⚠️ 90/270 时【宽高互换】）
   GPinX / GPinY             全局锚点（pin）位置
   LocPinX / LocPinY         pin 相对图形左上角的偏移（R=0.5 时已给出绝对值）
   FlipX / FlipY             镜像

→ 左上角坐标：left = GPinX - LocPinX ;  top = GPinY - LocPinY

文字在 <Text> 里（可能嵌套多层，用 ''.join(el.itertext()) 再压空白）
```

## 三、判定泳道是「横」还是「竖」

```python
lane_shapes = [s for s in shapes if s['typ'] == 'SwimLane']          # 最可靠：看 Type
# 兜底（Type 缺失时）：
#   横向带 = w > 3000 且 h < 600     → 一堆宽扁矩形上下堆叠
#   垂直列 = h > 1200 且 w < 900     → 一堆高窄矩形左右并列
```

```
⭐ 7 条横向带（自上而下）：
   y=0     h=234   质量保证部（QA）
   y=234   h=234   仓储部（收货人）
   y=468   h=269   WMS系统-RF
   y=737   h=210   WMS系统-WEB
   y=948   h=201   供应商
   y=1149  h=201   采购部门
   y=1350  h=201   ERP系统
   画布 3448 宽 × 1551 高；⭐ 另有一份第二圈副本（y≈5780）

⭐ 每条带只有【一行节点】高 → 不是"一个泳道塞满节点"，而是"流程一圈只走一层"，
   横向走完一圈 → 回顶部再走一圈（多圈推进）

节点上还带「系统/线下」小标签（WMS / RF / ERP / LIMS / 线下）与「接口」标记
```

### 从文字提取得出的业务逻辑（用户版）

```
开始 → 采购订单（ERP·自动·接口）→ 生成 ASN 单（WMS）→ 生效 ASN 单
→ 实物到货检查（线下）→ ⭐实物厂家是否与订单厂家一致？ ─否→ 拒收
→ 验收入库（RF）·页面字段 8 项：①外观检查(清洁/封签)是/否 ②物料信息(规格/型号/供应商)
  ③数量/件数 ④上传厂家报告 ⑤托盘码(可扫) ⑥生产日期 ⑦效期(按物料主数据算·可改)
  ⑧厂家批号(按批号生成规则)
→ ⭐是否称重？(查物料主数据)+称重规则表 → 称重(线下)+填写重量(RF)
→ ⭐是否记录温度？(查物料主数据) → 测量温度(线下)+填写温度(RF)
→ 入库确认（RF）→ 生成收货记录（WMS）→ ⭐库存状态默认：合格
→ ⭐是否请验？ → 生成请验单（WMS）→ 打印请验单/入库检查记录 → 交至质量（线下）
→ ⭐是否推送 LIMS？(查"是否线上请验") → 推送 LIMS → 生成请验单(LIMS)
→ 取样 / 请验放行 → 更新 WMS 库存状态 / 更新请验单状态 → 上架(RF)
→ 打印标签、打印托盘码（线下）→ 结束
```

### ⭐ 从「对方的图」反查矛盾（验证顾问的高价值动作）

把对方的图和 **URS / 现状口径** 对齐，挑出 4 处冲突 —— 这类问题对方自己看不出来：

| # | 对方图里的写法 | 与什么冲突 | 为什么要提 |
|:-:|--------------|-----------|-----------|
| 1 | 库存状态默认「**合格**」 | 后面又有「是否请验 → 生成请验单 → 请验放行」；公司标准模板《成品入库.eddx》是「默认待检」；GMP 要求未放行不得使用 | 逻辑自相矛盾 + 合规风险 |
| 2 | 有「是否推送 LIMS / 生成请验单(LIMS)」 | 此前口径是「客户无 LIMS」 | 确认是**预留接口**还是确有 LIMS |
| 3 | 「采购订单（ERP·自动·接口）」 | 此前口径「ERP 不打通」 | 同上；若不通则应落成"手工创建 ASN 单" |
| 4 | 缺 ASN 审核环节（生成→生效·自动） | URS7.4-9 要求入库订单支持审核/取消审核并记录审核人+时间 | 有管控需求就要补节点 |

⭐ 通用做法：**拿到对方的图 → 逐节点回 URS/SOW 对口径 → 出「矛盾清单」**，
不要只说"你这版少了 XX"，而是给"你这处和 URS/现状不一致，需要确认是 A 还是 B"。
（同类动作见 `references/scope-change-and-gap-audit.md`）

## 五、踩过的坑

```
① 不去命名空间前缀 → 遍历不到任何 Shape（本次第一次跑出 0 个形状）
② 提文字用 >([^<>]{1,90})< 会把同一段文字抓两遍
   （Edraw 把 形状+文字域 放 Group 里，各带一份 Text）→ 去重
③ thumbnail.jpeg 只有 3~4KB，视觉模型也读不出内容 → 别指望缩略图，
   直接解析 XML 坐标
④ ConnectLine 的【端点拓扑】本次没解析出来：连线点存在 <LineTo>/<X>/<Y> 折线里，
   没有稳定的 BeginConnect/EndConnect 子元素 → 要还原"A→B"关系时，
   按几何邻近（端点坐标落在哪个形状的 bbox 内）推断，或干脆照文字逻辑重排
⑤ ⚠️ ⭐ 泳道【内部】的节点，其 GPinX/GPinY 可能是【相对泳道】的局部坐标：
   此时 left = GPinX - LocPinX 会算出 0（本次一批节点的 x/y 全是 0 就是这个原因）。
   → 判定与修法：若某形状的 left/top 恒为 0，先把它的父泳道 bbox 加上：
     node_abs_x = lane_left + node_rel_x
   ⭐ 只做「泳道清单 + 节点文字清单」时不受影响（泳道本身的 GPin 是全局的）；
     但要给节点画坐标/复现布局，必须先补父偏移
```
