# 泳道流程图布局策略（蚂蚁搬家式试错记录 + 贪吃蛇正解）

> 用户对同一张图（采购收货·34 节点·39 连线·6 泳道）连续要求了 5 轮布局调整。
> 本文记录**每种布局的实测画布尺寸、优点、致命问题**，以及**最终被用户认可的方案**。
>
> ⭐⭐ 结论先行（2026-10-16 修订·务必按这个来）：
> **默认 = 垂直泳道列 + 全局流程序号 + 走廊路由（§8）**。
> ⚠️ 「横向蛇形 / 贪吃蛇」（§4）**已被用户否掉** —— 原话：*"还是放弃『贪吃蛇』吧，还是选择原泳道设计"*。
> ⚠️ 「连线不给 waypoints、交引擎自动路由」**也不够** —— 实测用户仍反馈"很乱"，必须自己控制走廊（§8）。

---

## 0. 布局决定了「连线会不会穿框」——这是根因，不是细节

用户的两句投诉其实是同一个病根：

```
① \"连接线之间不要重叠或重合\"
② \"节点间连接线不要碰到节点框\"
```

⚠️ 早期我一直在\"调锚点、算航点\"这一层打转（甚至越调越糟，见 §1 的 35 处穿框）。
**真正的解在布局层**：只要相邻节点在空间上物理相邻，连线就是短线，就没有机会穿框。

判据：**桥接距离** = 相连两节点在图上的几何距离。
- 距离大 → 线必须绕 → 必穿框（无论锚点/航点怎么算）
- 距离小 → 线是短线 → 天然安全

所以布局的首要目标：**让\"流程时间上相邻\"的节点，在\"图面空间上\"也相邻**。

---

## 1. ❌ 布局 A：垂直泳道列 + 泳道内独立排序（最初版·错得最狠）

```
样式：每列一个岗位（ERP | 采购 | 供应商 | WEB | RF | 仓储）
编号：泳道内序号 0,1,2…（每个泳道各自从 0 开始）
```

**致命问题**：同一水平高度上**堆着多个泳道的节点** → 跨泳道连线只能\"横穿\"
→ 必然穿过中间泳道的节点框。

实测：几何校验 **35 处穿框**（\"ed4(w2→b2) 横段 y=300 穿过 p2\"…）
用户截图反馈：\"现在连接线还是很乱\"

```
诊断脚本（锚点种类数）也会指向这里：
· 旧版锚点种类 = 1 种（全用\"底部→顶部\"）→ 必然重叠
```

---

## 2. ⚠️ 布局 B：垂直泳道列 + 全局流程序号

```
改动：把\"泳道内序号\"换成【全局流程顺序号】→ y = 全局序号 × 行高
效果：节点沿对角线下行，连线变成\"短阶梯\"
```

**优点**：泳道内天然自上而下（全局顺序 = 逻辑顺序），连线短了很多。
**遗留**：图**纵向很长**（34 行 × 100 ≈ 3600px 高），且跨泳道仍有水平段。

⭐ 这一步是对的（全局顺序 > 泳道内独立编号），可以保留作为备选。

---

## 3. ⚠️ 布局 C：横向泳道带 + 时间轴（一格一节点）——宽度爆炸

```
改动：泳道改成【水平带】（岗位横着排）；节点 x = 时间序号 × 列宽
效果：连线永远朝右（时间推进方向）→ 不回头、不交叉 ✅
```

**致命问题**：**一格一节点** → 34 个时间点 × 列宽 210 + gap 40 ≈ **画布宽 9160px** ⚠️

```
实测：9160 × 3690   ← 太宽，用户没法用
```

⭐ 教训：**列数不能按\"节点数\"算，要按\"单条带里最多的节点数\"算**。
   每条带的宽度由该带节点数决定 → 总宽 = max(每带节点数) × (列宽+gap)。

## 4. ✅ 布局 D：横向泳道带 + 蛇形排列（用户说的「贪吃蛇」·最终方案）

用户原话：*\"你参考一下贪吃蛇的规则，现在连接线还是很乱\"*

```
【蛇形规则】
① 每个岗位 = 一条【水平泳道带】，自上而下排列（6 条带）
② 带内节点按流程先后排（不是按时间槽占位，而是紧凑排列）
③ ⭐ 偶数带 左→右；奇数带 右→左 → 相邻带的\"衔接口\"在相反侧 = S 形（蛇形）
④ 列数 = max(各带节点数)，不是节点总数
```

```python
# 核心代码（build() 里的横向定位）
for b in range(nband):
    for k, (nid, txt, tp) in enumerate(bn[b]):
        if b % 2 == 0:                       # 偶数带：左→右
            x = 40 + k * (col_w + col_gap) + col_gap / 2
        else:                                # 奇数带：右→左（蛇形回头）
            x = CW - 40 - (k + 1) * (col_w + col_gap) + col_gap / 2
        y = by[b] + PAD / 2 + k * (RH + RGAP)   # 带内节点逐行下移
```

```
实测：4830 × 3688   ← 比布局 C 窄了一半
（其中 WMS-RF 带 15 个节点决定了宽度；必要时可把该带折成两行）
```

**连线策略**：⭐ 不给 waypoints，只给锚点，交 draw.io 自动正交路由。
锚点自动选择：水平距 > 40 → 左右出口；同带/近列 → 上下出口。

**各带节点分布（实测）**

```
ERP系统 1 ｜ 采购部门 2 ｜ 供应商 2 ｜ WMS-WEB 8 ｜ WMS-RF 15 ｜ 仓储部 6
                                                            ↑ 决定画布宽度
```

⭐ 带顺序建议按**流程推进方向**排（上游在前），并把节点最多的带放在中部——
   否则最宽的带贴着边缘，视觉很失衡。

## 6. ⭐ 交付这类\"布局反复调\"任务的沟通纪律

```
① 每次改完先说【改了什么机制】，再说效果 —— 不要只发文件让用户自己找不同
   （\"这次把布局从垂直泳道换成了横向泳道带 + 蛇形\"）
② 顺带说明【服务器没装 draw.io·我无法预览渲染】→ 请用户打开验证
   ⭐ 诚实标注能力边界，比假装\"已确认没问题\"强得多
③ 试过多个方案时，主动给【对比表】让用户选方向（本文 §5）
   —— 用户一句\"哪种对\"就能定方向，省掉再来一轮
④ 用户说\"你看一下图找问题\"时：要能列【具体哪几个框被穿】
   （\"8.1.1 校验供应商」「8.1.1.1 RF报错」「9.2.1.2 录入称重」都有竖线穿过\"）
   —— 泛泛说\"线有点乱\"会被认为没看
```

## 7. 待确认选项面板（布局 D 的标配·用户硬要求）

用户：*\"橙色判断框统一移到最右侧按节点序号排列\"*

```
主图（泳道带 + 节点 + 连线）  │  ⭐ 待客户确认选项面板（右侧独立列）
                                │  1️⃣【对应节点 5.】… ☐A ☐B
                                │  2️⃣【对应节点 8.1】…
```

```
· 面板宽 560；pageWidth = 主图右边界 + 40 + 面板宽 + 40
· pageHeight = max(主图高, 面板所需高)   ← 面板更高时别被裁掉
· 卡片 = 橙虚线圆角框（#fffdf5 / #d79b00 dashed）

```

## 8. ✅✅ 最终定稿：垂直泳道 + 全局顺序 + 走廊路由（0 穿框·几何验证过）

### 8.1 为什么绕回来了

```
① §4 横向蛇形（贪吃蛇）实测 4830 宽 —— 用户仍嫌乱，明确否掉：
   "还是放弃『贪吃蛇』吧，还是选择原泳道设计"
   → 教训：**布局是视觉偏好**，用户说回退就回退，别拿"我算过更优"去顶。

② §18「不给 waypoints 交引擎自动路由」也不够 —— 用户看渲染图仍说"很乱"
   → 引擎的自动避让不是万能的（尤其跨 3~4 个泳道的长线）。

⭐ 真正的解不是"换布局"，而是**把连线的走位规则定死**：
   水平段只在【全局行间隙】走，垂直段只在【泳道间走廊】走。
   → 布局回到用户熟悉的垂直泳道，连线也能做到 **几何验证 0 穿框**。
```

### 8.2 ⭐⭐ 两条铁律（这是全部要点）

```
【铁律 1 · 水平行走 → 只能走在「全局行间隙」】
  y = 90 + 65 + k*vgap + 102     其中 k = min(源行号, 目标行号)
  ⭐ 为什么是 +102：行高 134、矩形节点高 54、菱形节点高 78
     → 该 y 落在 {78..132} 与 {54..132} 的交集里，**任何泳道、任何行号的节点都不占这个高度**
  ⚠️ 早期错误：用"两节点之间的中点"当水平带 → 不同泳道行号不同，
     那个 y 在中间泳道可能正好是某个节点的行 → 横线必穿框（本次实测 6 处）。

【铁律 2 · 垂直行走 → 只能走在「泳道间走廊」】
  泳道间距留 110px；走廊 = 泳道之间的空白带
  向右跨泳道：cs = 源泳道右边界外的走廊；ct = 目标泳道左边界外的走廊
  向左跨泳道：反之
  ⚠️⚠️ 关键坑：走廊坐标做"防重合偏移"时**必须夹紧在走廊区间内**
     否则 slotting 把走廊推到 ±40px 就落进相邻泳道内部了 → 竖线穿框。
     （本次就是踩这个：1688 被偏移到 1648/1728，正好压进 WMS-RF / 仓储部）
```

```python
def gap_range(lane, side):
    """走廊可用区间 (lo, hi, center)"""
    if side == "R":
        lo = LX[lane] + lanes[lane][1] + 12
        hi = LX[lane+1] - 12 if lane+1 < len(LX) else lo + 60
    else:
        hi = LX[lane] - 12
        lo = LX[lane-1] + lanes[lane-1][1] + 12 if lane-1 >= 0 else hi - 60
    if hi <= lo: lo, hi = hi - 40, hi
    return lo, hi, (lo + hi) / 2

class Track:
    """全局通道表：水平/垂直各一个 set，冲突则偏移，且偏移夹紧在 [lo,hi]"""
    def __init__(self): self.h = set(); self.v = set()
    def h_slot(self, base, gap=20, lo=None, hi=None):
        x = int(round(base)); k = 0
        while x in self.h:
            k += 1
            x = int(round(base + (k*gap if k % 2 else -k*gap)))
            if lo is not None:
                if x < lo: x = lo + k*2
                if x > hi: x = hi - k*2
        self.h.add(x); return x
```

### 8.3 路由分支（同一函数里三分支）

```
① 同泳道 + 相邻行 + x 接近        → 直接上下（无 waypoints，最干净）
② 同泳道 + 跳过中间行（span > 1） → 绕【本泳道外侧走廊】：
     源右边缘 →(水平)→ 走廊 →(垂直)→ 行间隙 →(垂直)→ 目标行 →(水平)→ 目标右边缘
③ 跨泳道                          → 源侧走廊 + 目标侧走廊，中间用【全局行间隙】横向穿越：
     (源边缘,scy) → (cs,scy) → (cs,chy) → (ct,chy) → (ct,tcy) → (目标边缘,tcy)
     ⭐ chy 必用铁律 1 的全局行间隙 → 横穿再多泳道也不碰任何节点
```

⚠️ 「跳过分支」（如 `是否供应商管理 → 跳过校验直达登记初检`）是穿框高发区，
   因为它在同泳道内**跨越 3~5 个被跳过的节点** → 必须走分支②的外侧走廊。

### 8.4 交付前必跑的几何验证（唯一能说"0 穿框"的依据）

```python
import re
x = open('x.drawio', encoding='utf-8').read()
LX = {int(m.group(1)): (int(m.group(2)), int(m.group(3)))          # lane -> (x, w)
      for m in re.finditer(r'<mxCell id="lane(\d+)"[^>]*><mxGeometry x="(\d+)" y="90" width="(\d+)"', x)}
R = {}                                                            # 节点全局矩形
for m in re.finditer(r'<mxCell id="(\w+)"[^>]*style="[^"]*(?:rhombus|rounded=0|ellipse)[^"]*"'
                     r' vertex="1" parent="lane(\d+)"><mxGeometry x="(\d+)" y="(\d+)" width="(\d+)" height="(\d+)"', x):
    nid, ln, gx, gy, w, h = m.groups()
    lx, lw = LX.get(int(ln), (0, 0))
    R[nid] = (lx + int(gx), 90 + int(gy), int(w), int(h))

bad = []
for m in re.finditer(r'<mxCell id="ed\d+"[^>]*edge="1" parent="1" source="(\w+)" target="(\w+)"'
                     r'[^>]*><mxGeometry[^>]*>(.*?)</mxGeometry>', x, re.S):
    s, t, geo = m.groups()
    if s not in R or t not in R: continue
    pts = [(float(a), float(b)) for a, b in re.findall(r'<mxPoint x="(\d+)" y="(\d+)"', geo)]
    sx, sy, sw, sh = R[s]; tx, ty, tw, th = R[t]
    path = [(sx+sw/2, sy+sh/2)] + pts + [(tx+tw/2, ty+th/2)]
    for i in range(len(path)-1):
        (x1,y1), (x2,y2) = path[i], path[i+1]
        for nid, (rx, ry, rw, rh) in R.items():
            if nid in (s, t): continue
            if abs(x1-x2) < 1.5:          # 竖段
                if rx-1 < x1 < rx+rw+1 and not (max(y1,y2) < ry or min(y1,y2) > ry+rh):
                    bad.append(f"{s}→{t} 竖线穿{nid}")
            elif abs(y1-y2) < 1.5:        # 横段
                if ry-1 < y1 < ry+rh+1 and not (max(x1,x2) < rx or min(x1,x2) > rx+rw):
                    bad.append(f"{s}→{t} 横线穿{nid}")
print(f"穿节点框: {len(bad)} 处"); [print("  ·", b) for b in bad[:10]]
```

⭐ 这条验证是**唯一能让"线不穿框"变成可判定事实**的手段（不是肉眼看）。
   回话直接给数字："几何验证：0 处穿框（逐条线段与节点矩形求交）"。
⚠️ 改一次路由就重跑一次；修好一处常会新引入别处（本次 35 → 7 → 6 → 0）。
