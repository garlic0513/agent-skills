# 节点怎么写：业务为中心 / RF 端 / 配色三问答

> 来源：2026-10-26 用户连问三题（「流程图是以产品为中心吗」「RF 端在流程图里怎么体现」「蓝底代表什么」）
> 用途：画每个节点、回答评审提问时，先过这一篇。

## 一、流程图是【业务为中心】，不是【产品为中心】

用户原话：*"流程图是从产品角度设计的文档，流程还是以产品为中心进行动作编排的。我这么理解有问题吗"*
→ **有问题，方向要调**：以业务为中心，产品只做约束。

| | 业务为中心（正确） | 产品为中心（错） |
|---|---|---|
| 主语 | 人（采购员/收货员/第二人/QA） | 系统（界面/菜单/按钮） |
| 动作 | 业务动作（核对/扫码/判定/搬运/放行） | 交互动作（点击/填入/提交） |
| 例 | 「收货员扫箱码，系统带出批次」 | 「在条码输入框录入箱码」 |
| 系统在哪 | 只做**右上角小标签**（WMS / WMS-RF / ERP） | 写成节点本身 |

### 两个一秒判据

```
① 把系统名、菜单名删掉，这句话还成立吗？   成立=业务节点 ✓   不成立=功能节点 ✗
② 能填进「谁 + 做什么 + 对什么」三格吗？   能=业务 ✓       只能填"点了哪个按钮"=功能 ✗
```

### 用户理解里对的部分（要肯定，但归到别处）

流程确实受**产品能力约束**（不能画系统做不到的动作）——正解是
**「业务动作为中心，产品能力为约束，产品模块用另一张《节点 ↔ 模块对照表》承载」**。
所以图里不写功能名，但**配一张对照表**：节点号 → 模块名。评审看图、实施看表，两边不打架。

### 三种流程图别混

| 类型 | 中心 | 读者 | 用在哪 |
|---|---|---|---|
| 业务流程图（泳道图） | 业务动作+角色+单据 | 客户业务部门、QA、审计 | 蓝图正文、评审 |
| 产品功能流 / 界面流 | 菜单、页面、按钮 | 实施、开发、培训 | 培训手册、配置说明 |
| 接口 / 数据流 | 系统间数据 | 技术、验证 | IQ/OQ、接口清单 |

⚠️ 以产品为中心的后果（会在评审现场爆）：客户说"我们不这么干"→ QA 问"控制点在哪"答不上 →
URS→蓝图→OQ 用例链断 → 换个 WMS 图全废。

## 二、RF 端（手持终端 / PDA）怎么体现

**RF 不是节点，是标签**——工具不是动作，流程里没有"用 RF"这一步。

```
① 首选：节点贴【RF 或 WMS-RF】系统小标签（浅黄 38×21，右上角或右侧外侧）+ 白底（人动手扫码）
② 图太密时：写进节点文字前缀 —— 「65 RF扫箱码归组到实物托盘」
③ 图例页写一句：RF＝手持终端扫码作业，动作在收货现场/库位现场，不在电脑前
④ 同一条流程内统一用 ①或②，别混
```

### 三个错误

| ✗ | 为什么错 | ✓ |
|---|---|---|
| 把 RF 画成独立节点 | RF 是工具，不是动作 | 标在动作节点的标签上 |
| 同一节点贴 WMS + RF 两个标签 | 重复——RF 就是 WMS 的移动端 | 只写 `WMS-RF` 或只写 `RF` |
| RF 节点用浅蓝底 | 蓝=系统自动，扫码是人做的 | 白底 + RF 标签 |

### RF 的隐含信息（评审会读，也是布线依据）

```
① 作业在现场（收货区/库位前），不在办公室 → 布局上可放在"现场"泳道
② 必须扫到码才产生数据（不能凭记忆录入）→ 佐证"消除手录"的控制强度
③ 断网/终端故障会直接卡住作业 → 需要应急预案（手工单 + 事后补录），否则审核问"
   系统不可用时的替代控制是什么"
```

⭐ 分工口径：**电脑前做 → WMS 白底；现场扫码 → WMS-RF 白底；不用系统 → 灰底（线下）。**

## 三、配色三问答（用户会指着图逐个问）

```
Q 蓝底代表什么？
A 这个动作由【系统】做：矩形=系统自动执行；菱形=系统判断（系统校验后自动分支）

Q 为什么这个不能是蓝底？
A 蓝 ≠ "跟系统有关"，而是"系统自己会做"。人在系统里点/录/打印/审核 → 白底

Q 泳道标题条也是浅蓝，也是系统操作吗？
A 不是。那是泳道本身的底色（部门/岗位），最容易混的一处——它不表达任何操作语义
```

### 完整语义表（统计模板实测）

| 语义 | 表现 |
|---|---|
| 人工操作（人在系统里做） | 白底矩形 |
| 自动 / 系统执行 | 浅蓝 `#DAE8FC` 矩形 |
| 系统判断 | 浅蓝菱形 |
| 线下操作（不碰系统） | 浅灰 `#EEEEEE` 矩形 |
| 人为判断 | 浅灰菱形 |
| 单据 / 附件 | 右下角浅粉 `#FDEDEC` 标签 |
| 系统名 | 右上角/右侧浅黄 `#FFF2CC` 小标签 |

⚠️ **打印 / 上传 / 下载 类节点：无论白底蓝底，都必须加右下角浅粉单据标签**（说明"打印了什么单"）——
这一条最容易漏，评审一眼就看得出（例：「170 打印物料标签」缺单据标签 + 用了蓝底，两处都不对）。

## 四、连带的一条交付纪律

用户常接着问「**那这个节点的编号/名称给我，我自己改图**」——
⭐ 交付时先分清他是「要我重画」还是「只要数据」：
要数据 → 只给**编号+节点名称对照表（旧号→新号）**，不要顺手改图；改图反而增加他的核对量。
