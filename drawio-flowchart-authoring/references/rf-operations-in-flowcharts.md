# RF（手持终端 / PDA）在流程图里怎么画 + 现场作业时间线

> 用户高频提问两类：①「RF 端在流程图中怎么体现」②「RF 相关的节点动作顺序是什么样，给我详细场景」
> 定稿：2026-10-26

## 一、铁律：RF 不是节点，是「系统标签」

RF（手持终端 / PDA / 扫码枪）是**执行工具**，不是业务动作。所以图上**不画「用 RF」这一步**。

| 画法 | 用什么 | 何时用 |
|---|---|---|
| **① 系统标签（标准）** | 节点右上角/右侧外侧贴 `WMS-RF`（浅黄 #FFF2CC 小方块） | 图不挤时首选，评审一眼看出"这步在现场扫码" |
| **② 文字前缀** | 节点名写 `65 RF扫箱码归组到托盘` | 展开版/高密度图（标签会压线） |
| **③ 图例统一说明** | 图例页写「RF＝手持终端扫码作业，动作发生在现场」 | 一页顶十处，配合 ①② 用 |

**同一条流程内统一用一种**，不要混。

## 二、配色与三个常见错误

```
· RF 操作 = 人动手 → 【白底】（人工），不是浅蓝
  浅蓝 = 系统自动执行，扫码是人做的，别上蓝
· 电脑前操作 → 标签写 WMS；现场扫码 → 标签写 WMS-RF；不碰系统 → 灰底
```

| ❌ 错 | 为什么错 | ✅ 对 |
|---|---|---|
| 把「RF端」画成一个独立节点 | RF 是工具不是动作，流程里没有"用RF"这一步 | 标在动作节点的标签上 |
| 同时贴 `WMS` 和 `RF` 两个标签 | 重复——RF 就是 WMS 的移动端 | 只写 `WMS-RF` |
| RF 节点用浅蓝（自动） | 扫码是人手动完成的 | 白底 + 标签 |

## 三、标了 RF 隐含的三条信息（评审会看）

```
① 作业在现场（收货区/库位前），不在办公室
② 必须扫到码才产生数据（不能凭记忆录入）→ 这就是"消除手录"这一类控制
③ 终端/网络故障会直接卡住作业 → 必须有应急预案（手工单 + 事后补录）
```

⭐ 所以 RF 不只是标记，它回答了"这条流程在人不在电脑前时能不能跑通"。
→ 判断某一步该不该标 RF 的问句：**「这个动作是人站在货旁边做的，还是坐在电脑前做的？」**

## 四、RF 收货现场时间线（可直接照着讲 / 写 SOP）

场景：1 个托盘 20 箱，收货员手持 PDA。

| 序 | PDA 上的动作 | 屏幕/交互 | 后台系统做什么 | 流程图节点 |
|:-:|---|---|---|---|
| 1 | 扫工牌登录、选仓库 | 用户名/密码/仓库 | 记录登录人、设备、时间 | （前置，不画） |
| 2 | 选作业类型 | 收货／上架／拣货／移位／盘点／查询 | 权限校验 | （前置） |
| 3 | 扫订单/ASN | 扫单号或选单 | 校验单据状态、带出应收数 | `RF选择订单` |
| 4 | **扫托码** | 整托收货／拆托收货 | 校验托码注册状态、是否被占用、带出箱清单 | `RF扫托码` |
| 5 | **逐箱扫箱码** | 已扫 n/N 进度 | 校验箱码、**拦混批/重复扫** | `RF逐箱扫箱码` |
| 6 | （无需操作） | 显示物料/批次/效期/箱规 | 扫码带出，**字段不可编辑** | `系统带出批次` |
| 7 | 录实收数量 | 默认=理论数；改数必须选原因 | 容差判定 | `RF录实收数量` |
| 8 | —（系统弹提示） | "超出容差，需处置" | 生成差异单、通知采购 | `超收短收？` → 子流程 |
| 9 | **扫收货库位码** | 扫库位 | **校验库位类型与库存状态匹配**（待检品不能进合格区） | `RF扫收货库位` |
| 10 | 点【提交收货】 | "收货成功·单号·待检库存" | 写收货记录 + 生成待检库存 + 建请验单 + 审计追踪 | `RF提交收货` |
| 11 | **换 PC 端** | — | 主管在电脑上对比系统数/实收数，确认或退回 | `复核（第二人核对）` |

⭐ **最重要的分工**：**RF 只"做事"，不做"复核"**。复核要左右对比、要写理由，PC 大屏才合适。

## 五、RF 现场六个必遇异常（图上每个扫码节点后都该有判定）

| 现象 | PDA 提示 | 处理 | 图上表达 |
|---|---|---|---|
| 箱码破损扫不出 | "条码无效" | 手工输码 → 主管授权 | 扫码节点后加「码可读？」判定 |
| 同一箱扫两次 | "该箱已扫描" | 自动忽略，不重复计数 | 防错，不画分支 |
| 一托混批 | "检测到混批" | 拆托分批 或 整托退回 | 「批次一致？」判定 → 拆托/退回 |
| 数量超容差 | "超出容差" | 走超收短收处置子流程 | 指向差异处置 |
| 扫错库位（合格区） | "库位类型不符" | 重扫至待检区 | 「库位类型匹配？」判定 |
| 网络中断 | "离线模式，数据暂存" | 恢复后批量上传，需确认无重号 | 虚线框标「离线作业」（可选） |

## 六、三条 RF 特有的画图约束

```
① 顺序不可跳：不扫库位不能提交、不扫箱码不能输数量
   → 图上用【线性直连】表达，不画并行分支
② 错误当场拦：每个扫码节点后面都要有「是/否」判定
   → 没有判定的扫码节点 = 漏了异常路径（完整性直接扣分）
③ 离线缓存是需求，不是实现细节：客户若无离线要求，写明"网络依赖现场 Wi-Fi"
```

## 七、自检

```
□ RF 相关节点是白底 + WMS-RF 标签（不是独立节点、不是浅蓝）
□ 每个扫码节点后都有判定（码可读/批次一致/库位匹配）
□ 复核在 PC 端，不在 RF 端
□ 图例页有一条 RF 说明
```
