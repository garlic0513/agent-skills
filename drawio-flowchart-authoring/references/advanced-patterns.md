### 十三·补、⭐⭐ 第 1 页放「总览页」（索引 + 跳转）· 三个生成坑

用户会追加一句「**能不能在第一页加个总览**」——这是多页文件的标准形态，别当成新需求重画。

**总览页布局（已实测好用）**

```
左列：N 个主流程卡片（竖排，各自 link 到自己的页）
中部：公共子流程大框（被所有主流程调用）
右上：条件型子流程（如质检·虚线「需要时」）
右下：收尾子流程（如上架）→ 右端「流程结束」胶囊
底部：3-4 条说明条（主线怎么走 / 客户环境适配 / 怎么用（Ctrl+点击）/ 配色语义）
```

⭐ **多条主线汇入同一个公共子流程时，给每条边不同的 `entryY`（0.15/0.32/0.5/0.68/0.85）**
→ 形成扇形汇入，否则 N 条线全压在目标同一个点上，看起来像一根粗线。

**三个生成坑（本次连续踩到）**

```
① ⚠️⚠️ 属性值里不能出现裸标签：value="标题&#10;<font style=&quot;…&quot;>副标题</font>"
   → `ParseError: not well-formed (invalid token)`。XML 的属性值里 `<` 必须转义，
     写 &quot; 只是转引号，救不了 `<`。
   ⭐ 正解：整段文本先 html.escape 再 replace('\n','&#10;')，不要手写任何标签：
      value="{esc(主标题 + chr(10) + 副标题)}"     （放弃 font 标签，靠 fontSize/fontStyle 调）
② ⚠️ 把总览页插到第 1 页 → 后面所有页 id 全体后移一位（pg1…pgN 全变）
   → 页内跳转链接必须【在插入之后】重新映射，否则跳到错页/空页。
   ⭐ 顺序固定为：先定页序 → 再算 id → 最后注入 link。
③ ⭐ link 直接写成 mxCell 的独立属性最省事：<mxCell id="m1" value="…" style="…" vertex="1"
     parent="1" link="data:page/id,pg2">  （不必塞进 style，也不必加 # 前缀）
   写成 style 里的 link=#data:page/id,xxx 也可，两种都能跳。
```

**自带自查（交付前报数给人看）**

```python

          f"连线{len([x for x in c if x.get('edge')=='1'])} 跳转{len(links)} 死链{bad or '无✅'}")
```

⭐⭐ **用户一定会问「从总览页的跳转是不是有问题」** —— 先别怀疑自己写错了，按这个顺序回：

```
① 先核事实：link 值 data:page/id,<id> 与 <diagram id="..."> 是否一一对应
```

### 十三·补2、⭐⭐ 泳道内【两列布局】的算法与 6 类路由（2026-10-19 实测·公司模板风格默认）

用户在"线太乱"连提数轮后，正解不是调锚点，而是把**泳道内拆成两列**（公司标准模板就是这么画的）：

```
① 行号：start→end 最长简单路径 = 主干，row 0..N 连续 → 主干不再被异常节点占行，
   「流程结束」紧跟在最后一个主干节点后面
② 旁路：不在主干的节点按出边连通分块，块内拓扑序依次占行，块首行 = 分支源所在行
   → ⭐ 异常节点落在【分支点同一行】的左侧列 → 分支线变成 0 折点的纯横线
③ 列宽：泳道宽 = max(200, 40*2 + 列数*100 + (列数-1)*72)（与模板"泳道宽度按内容自适应"一致）
④ 通道：列间缝(56px) 给同泳道绕行/跨列；⭐ 泳道之间【不留走廊·紧贴】（用户 2026-10-19 原话
   （用户 2026-10-19 原话「还有泳道间是贴着的」，公司标准模板本身也是 0 间距）；行间隙给跨泳道的横穿
⑤ 6 类路由（有走廊版）：同列相邻=直线 / 同列跳行=列间缝 / 同排跨列=纯横线 /
   异排跨列=列间缝 L / 跨相邻泳道两端都在主干列=走廊 L / 有一端在旁路列=行间隙绕行
⑥ ⭐⭐ 泳道紧贴版（CORR=0，2026-10-19 定稿）→ 只剩 5 类，跨泳道统一改【行间隙阶梯】：
   出源上/下边 → 行间隙横穿 → 进目标上/下边（2 个折点，永远不穿框）
   ⚠️ 别想\"借两泳道之间的缝走竖线\"——紧贴后没有缝，硬走必穿隔壁泳道的节点
   ⚠️ 行间隙阶梯会让横穿段变多（同一页交叉 6→11），但全在间隙里、不打架；
      折点/线反而降到 1.54、总线长 −8%
```

三个必踩的坑（都实测翻车过）：

```
⚠️ 跨列时【出口看源、入口看目标】必须分别判断左右；用一个 side 判两边 → 必然反（线从框里穿出）
⚠️ "行间隙绕行"必须【两端都走行间隙】。只让一端走，另一端的竖线会顺着主干列一路穿框
   （实测 c9→c18 竖线 900px 穿过 8 个节点）
⚠️ 旁路节点可能在【别的泳道】（如"不合格"链跨 QC→QA→仓储），别硬走横线穿自己泳道的主干列
```

⑦ ⭐【是/否 标签贴菱形尖角】（用户原话「\"是\"和\"否\"距离棱形节点的角稍近一些，方便人观看」）
   边标签默认落在【整条线的中点】→ 像\"否\"这种要绕到页底的线，字被甩到离菱形很远的地方。
   正解：给标签的 mxGeometry 写 `x=\"-0.78\" relative=\"1\"`，把它压到【源端】，就贴在尖角旁了。
   （只对带标签的边加，无标签的边保持 `relative=\"1\"`）

### 十三·补3、⭐⭐ 新增 / 改造一个【子流程页】的标准动作（本例：加"初检子流程"）

用户说「我想加一个 XX 子流程」——不要只新建一页，**四处都要动，漏一处就断链**：

⭐ 动手前先拷问一轮（**每问带默认值**，他可以一句「按默认」通过，别问成三轮）：
```
1 定位：替代现有节点 还是 新增？        → 默认：能替代就替代（消掉重复）
2 范围：只挂一条主流程 还是 全部？      → 默认：只挂真正用到的那条 + 公共子流程
3 人　：要不要拆新泳道？                → 默认：不拆，等客户确认分工
4 内容：步骤清单（列出来）要砍/要加？    → 默认：按列出的
5 判定：系统判（蓝菱形）还是人工判（灰）？→ 默认：看得见人判断的用灰
6 页序：新页排第几？                    → 默认：追加到最后（避免 pg id 重映射）
7 命名：叫什么？                        → 默认：××子流程
8 配套：要不要同时写文字说明？          → 默认：图定了再写
```
交付时列一行「哪几条按默认做的」，他要改只需点编号。

```
① 新建页数据（lanes/nodes/edges）→ 追加到 PAGES 末尾
   ⭐⭐ 【追加在最后】= 新页 id 顺延为 pg10，已有 pg2..pg9 的跳转全部不用改
      （若插在中间，全体页 id 后移，所有 link 必须重映射——§十三·补 坑②）
② 调用点接线：在主流程页放一个 sub 类型框（双线框）+ link="data:page/id,pg10"
   ⭐ 同时【收敛重复节点】：新子流程常常吸收主流程里已有的散步骤
      （本例第2页把"目检并清点数量 / 目检通过? / 拒收"三个节点并成 1 个调用框）
   ⚠️ 删节点要成套：删节点 + 删它的进出边 + 补一条上下游直连（见 §七）
③ 姊妹页联动：别的子流程里若有同一步骤（本例 S1 的"RF登记初检信息"、"是否称重/称重录入"）
   → 改成调用新子流程，把被吸收的步骤删掉，否则同一动作画两遍
④ 总览页：加一个框 + link="pg10" + 一条带标签的箭头（"初检合格后"→收货子流程）
   ⭐ 顺带核对每个卡片上的"主流程 N 步 / 公共子流程 N 步"——节点数变了要同步改，否则一眼假
```

### 十三·补3-b、⭐⭐ 改【一条已有主流程页】（不是新增子流程）：客户/PM 甩口语化 N 条口径

项目经理/客户会一次给 6–8 条口语化口径要求改某条主流程（本次：成品入库 8 条）。
**先落位成表、再动手画**，别边读边改：

```
① 逐条落位：他的原话 → 删/改/加哪个节点（交付时这张表就是他的核对清单）
② ⭐ 动手前先扫【逻辑缺口】——口语只说结果不说闭环，四处最常见：
   · "数量不符由上游改单" → 谁通知他改？改单留痕（原值/新值/原因/人/时间）在哪？
   · "扫码绑托盘" + "本方不打码" → ⭐ 托盘码谁生成、谁贴？（自相矛盾，必须问）
   · "质检后才上架" → 待检那几天货在系统里没有库位 → 补"上架到待检区库位，
     放行后移库到合格区"，否则盘点/追溯断链
   · "质检只记结果、复核后才放行" → 状态变更点必须挂在【复核】节点上，否则货永远待检
③ ⚠️ 加泳道 = 全页重算：本次加「质量保证部（QA放行员）」→ 3 条变 4 条，宽度/节点 x 全变；
   ⭐ 复核=放行归 QA 泳道（QC 取样检验、QA 放行，合并会被审计挑）
④ 删判定/删节点后编号必然前移 → 交付时主动列「哪几页从第几号起 −10」
⑤ 总览页卡片的"N 步"要同步改（节点数变了不改就是一眼假）
```

交付话术固定三段：**表A 你的口径→图上落点 / 表B 我补的闭环（可单独否决）/ 表C 仍需确认的 K 条**。
⭐ 他认这种"补了什么都摊开、可以单独否决"的交付方式，比默默改得分高。

### 十三·补4、⭐⭐ 跨系统【边界页】—— 讲清"我们负责哪一段"（本例：监管码全链路）

用户问「X 的流程一般是什么」或会上要划责任边界时，**单独画一页跨系统页**，别塞进主流程页：
