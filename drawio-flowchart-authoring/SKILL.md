# Drawio 流程图程序化生成 & 验收

> ⭐ 一句话：**流程图不是画出来的，是"定义数据 → 生成 → 几何校验 → 真渲染 → 打分"出来的。**

## 何时使用

- 用户说「画个流程图 / 泳道图 / 业务流程图」
- 要把 SOP、URS、岗位职责、会议口述的流程变成图
- 一次要出多张图（一条业务域 10–40 条流程）
- 用户说「这张图太乱 / 线穿过框 / 编号乱了 / 看不清」
- 要读别人发来的 `.drawio` / `.eddx`（万兴亿图）/ `.vsdx`（Visio）
- 要判断一张图「能不能交付」

## 何时不用

- 只要一张示意草图（手画/Mermaid 更快）
- 客户已有成熟图，只需改文字（直接改 XML 更省事，见 references/drawio-consistency-audit.md）

---

## 一、⭐ 核心工作流（七步，别跳）

```
① 定边界   起点是什么、终点是什么（不定边界必失控）
② 列角色   先定泳道（部门（岗位）），不画框
③ 列动作   用文字列清单："谁 + 动词 + 对象"，此时还没有图
④ 生成     把 ②③ 写成数据（lanes / nodes / edges）→ 脚本生成 XML
⑤ 几何校验 折点/线、交叉数、穿框数（脚本算，不靠肉眼）
⑥ 真渲染   用 draw.io 引擎渲染成图，自己先看一遍（脚本）
⑦ 打分     质量五维自评，8 分以上才交付
```

⭐ **第③步最关键**：先写字、后画框。直接拖框的人，画到一半必然返工。

## 二、节点与样式（六种，别自创）

| 类型 | 形状 | 语义 | 建议尺寸 |
|---|---|---|---|
| 起止 | 胶囊 ellipse | 流程开始 / 结束 | 78×38 |
| 操作（人工） | 直角矩形，**白底** | 人在系统里点击/录入 | 100–200 × 65 |
| 操作（自动） | 直角矩形，**浅蓝 #DAE8FC** | 系统自动执行 | 同上 |
| 操作（线下） | 直角矩形，**浅灰 #EEEEEE** | 纸质、搬运、目检（不碰系统） | 同上 |
| 判断（人为） | 菱形，**浅灰** | 人看图/看货判断 | 132×82 |
| 判断（系统） | 菱形，**浅蓝** | 系统校验后分支 | 132×82 |
| 子流程 | 双竖线框（`shape=process`） | 调用另一个流程图 | 同操作 |
| 单据 | 矩形 + 右下角浅粉标签 #FDEDEC | 产生/打印的单据 | — |
| 系统标签 | 小方块 #FFF2CC 38×21 | 贴节点右上角，写 WMS/ERP/RF | — |

**配色只表达三件事**：白＝人工、蓝＝系统、灰＝线下。不要因为"好看"加颜色。

**文字一律写在图形内部**（图形自己的 label），不要用浮动 text 单元格——否则改字时找不到。

## 三、泳道规则

```
· 泳道 = 部门（岗位），例：仓储部（收货员）｜仓储部（复核员）｜质量部（QC）｜质量部（QA）
· 执行岗与复核岗必须【两条泳道】——否则图上看起来还是一个人
· 质量"检验"与"放行"必须分开（QC 检、QA 放行），合并会抹掉关键控制点
· 管理岗一般不上日常动作；要出现就给一个审批类节点
· 泳道数 ≤ 6；超过就该考虑拆页或合并角色（但不要合并上面两类）
· 泳道列序按【流程先后】排，不按部门大小排
· 泳道必须紧贴（间距 0）或留固定走廊，二者择一全图统一
```

⚠️ **泳道 z 序坑**：draw.io 的层级 = XML 文档顺序。新增 swimlane 必须插在「其他泳道之后、所有节点之前」，**append 到末尾会盖住节点，看起来像"节点消失了"**。

## 四、编号规则

```
流程开始 → 10 → 20 → … → 流程结束

① 起止节点【不编号】（流程开始 / 流程结束 前面不加序号）
② 第一个动作从 10 起（不是 20，不是 1）
③ 步长全页统一（默认 10；节点特别密可用 5），不混用
④ 必须连续无断号；编号大小必须与【图上上下顺序】一致
⑤ 中途插节点只有两条路：
   a) 整体重排（首选，改完给"旧号→新号"对照表，方便同步文字说明）
   b) 用中间号插入（15/25/35…，前提是步长留了 5 的余量）
   ⭐ 不允许"随手编号"（跳到 170、或前面 +10 突然 +5）
⑥ 交付前自查：按图上 y 顺序抓 ^(\d+)，必须严格递增且等差
```

典型坏图：`10…90 → 95 → 170 → 120 → 130 → 140 → 160`（步长乱 + 顺序倒挂 + 缺号）

## 五、⭐ 布局：先选对结构，再谈连线

**连线穿框/太乱时，第一反应不该是调锚点，而是问"相连的两个节点在图上离多远"。**

距离大 → 线必须绕 → 必穿框。该动的是布局：让流程上相邻的节点，在空间上也相邻。

| 布局 | 结构 | 适合 | 注意 |
|---|---|---|---|
| **A 垂直泳道列 + 泳道内单列** | 一步一行 | 节点 ≤ 15 | 节点一多必然纵向爆炸 |
| **B 垂直泳道列 + 全局顺序号** | 一行一节点，跨泳道走走廊 | 中等复杂度 | 需自己控制走廊通道 |
| **C 横向泳道带 + 时间轴** | 一格一节点 | 展示型 | 宽度会爆炸（数千 px） |
| **D 泳道内两列（旁路左 / 主干中）** | 主干单列 + 异常节点占左列 | ⭐ 公司标准模板常用 | 交叉可降一个数量级 |

### 路由铁律（自算航点时）

```
① 水平段只走【全局行间隙】：y = 泳道顶 + 首行偏移 + min(源行,目标行)*行距 + 行内偏移
   ⚠️ 别用"两节点中点"当水平带——那在中间泳道可能正好是节点行
② 垂直段只走【泳道之间的走廊】，且做防重合偏移时必须夹紧在走廊区间内
   ⚠️ 偏移越界就落进相邻泳道内部 → 竖线穿框
③ 泳道紧贴（间距 0）时没有走廊 → 跨泳道统一用【行间隙阶梯】：
   出源上/下边 → 行间隙横穿 → 进目标上/下边（2 折点，永不穿框）
```

⚠️ **更省事的正解**：跨泳道/长距离连线**不给 waypoints**，只给 `exitX/exitY + entryX/entryY`，让 draw.io 用 `edgeStyle=orthogonalEdgeStyle` 自动正交路由 + 自动避让。手工算航点反而更容易造出穿框。

### 三个必踩的坑

```
⚠️ 跨列时"出口看源、入口看目标"必须分别判断左右；用一个 side 判两边 → 线从框里穿出
⚠️ 同一源节点同一出口角指向多个目标 → 线重叠（判断节点三出口要分散）
⚠️ 判断菱形的两条出边不能都走同一个角
```

## 六、一条流程压进一页：自适应行距/字号

节点数多、又要塞进一页时的公式（A3 横向 1654×1169 为例）：

```python
avail  = H - top - bottom                # 例 1169-118-26 = 1025
pitch  = avail / (max_row + 1)           # 行距
node_h = max(17, pitch - 8)              # 元素高必须 ≤ 行距-8，否则相邻相切
dia_h  = max(20, pitch - 8)
fs     = clamp(pitch * 0.245, 6, 10)     # 字号
```

**实测上限（A3 一页）**

| 节点数 | 泳道数 | 行距 | 字号 | 观感 |
|:-:|:-:|:-:|:-:|---|
| 13 | 3 | 72 | 10pt | ✅ 舒服，可投屏 |
| 35 | 5 | 33 | 7.9pt | ⚠️ 放大能看，打印勉强 |
| 40 | 6 | 29 | 7.2pt | ❌ 糊（35–80 号一段全挤） |

⭐ **可读上限 ≈ 34 个节点（有 6 条泳道时）**。超过就该三选一：合并冗余节点 / 精简泳道 / 拆两页，并主动告诉用户"这是数学极限，不是参数没调好"。

**压到极限时四处必改**

```
① 行号自动压缩（删节点后 max_row 不降 → 行距不变 → 字号不涨，白改）
② 判定菱形文字 verticalAlign=top（否则箭头压字）
③ 是/否 标签不要挂在线中点上，移到菱形右侧（offset x≈66）
④ 系统标签贴节点【右侧外侧】，不要贴上/右上（行距小时必压字）
⑤ 分支节点别靠横向微偏移错开（泳道窄，偏 50px 就重叠）→ 换空闲行或相邻泳道
```

## 七、⭐ 交付前：质量五维打分

**每维 0–2 分，满分 10；8 分以上才可交付评审。**

| 维度 | 2 分标准 | 0 分表现 |
|---|---|---|
| 正确性 | 业务同事认可"我们就是这么干的" | 画成产品功能流（点菜单/填框） |
| 完整性 | 每条异常分叉都有终点，无悬空箭头 | 只有主流程 |
| 可读性 | 新人拿图能照着独立做完 | 一页 40 节点糊成一团 |
| 规范性 | 配色/编号/泳道/图例全符合约定 | 自创图例、判定画成矩形 |
| 可维护性 | 加一步不用重画、编号可插 | 连号编号、坐标硬编码 |

📄 完整打分卡（含 12 条快速自检、12 条缺陷库、四级练习阶梯）：`references/quality-scorecard.md`

### 一条通用验收问句

> **"如果明天来个新人，拿着这张图能不能独立把这活干完？"** 不能 → 缺的就是要补的。

## 八、常见坑（都踩过）

```
① 泳道内子节点坐标必须【相对父容器】（x=30 这种），写绝对坐标 → 节点全堆到一处
② 新增泳道 append 到末尾 → 盖住节点（z 序=文档顺序）
③ f-string 里嵌三元表达式 → SyntaxError: f-string: expecting '}'
   先算变量 valign = 'top' if pitch < 34 else 'middle'，再嵌
④ Python 的 str.replace() 遇到转义引号会【静默失败、零报错】→ 改完必须 grep 关键串确认
⑤ 不要用 sed/正则改生成器 .py（长中文+引号会打断字符串字面量）→ 用 patch 或整份重写
⑥ 长脚本别用 heredoc 喂 python：长中文 + 2>/dev/null 会把真报错吞掉 → 先写 .py 再跑
⑦ 删节点先分清【普通 cell】还是【group 组合节点】：
   组合节点的文字在子 cell 里，按文字匹配删会留下空白框
   → 值命中的 id → 取 parent（group）→ 连子带壳一起删
⑧ 删判断节点 ≠ 只删一个框：它带两条出边，删前想清"剩下的分支还算不算"
⑨ 图有一页改了，文字说明表必须同步改 → 跑图↔表一致性核对，否则评审必挑
⑩ .drawio 交付前必做真渲染自查（见 reference），只看 XML 会漏掉文字溢出/标签压线
```

## 九、脚本（scripts/）

| 脚本 | 用途 |
|---|---|
| `drawio_swimlane.py` | 泳道图生成器：JSON spec → .drawio，含锚点智能选择 + 三出口 + 自查 |
| `check_line_overlap.py` | 几何校验：线穿框 / 通道重合 / 菱形误用上下口 |
| `check_lines_per_page.py` | 逐页体检：穿框·压线·**交叉**·折点每线·总线长（判"乱不乱"的量化指标） |
| `parse_drawio.py` | 解析任意 .drawio（兼容压缩/未压缩），概览泳道·形状·连线，`detail 关键词` 看明细 |
| `parse_eddx_geometry.py` | 解析 .eddx 几何：泳道横竖、带宽、节点落位（读别人草稿必用） |
| `make_drawio_preview.py` | 生成真渲染预览 HTML（配本地 http + 浏览器截图 = 交付前自验收） |
| `drawio_multipage.py` | 多个 .drawio 合并成多页 mxfile + 注入页间跳转 |
| `verify_drawio_multipage.py` | 多页文件逐页几何验证 |
| `template_style_diff.py` | 与参考模板做样式逐项 diff（治"被一条条挑视觉"） |

## 十、交付前检查清单

```
□ 图能打开、页数/页名正确
□ 几何校验：穿框 0、压线 0、交叉 ≤ 节点数/4、折点/线 ≤ 2
□ 真渲染看过一遍（文字不溢出、标签不压字、泳道里真有节点）
□ 编号连续等差、与图上顺序一致
□ 配色只三色（白/蓝/灰）+ 系统标签
□ 每条分叉有终点，每个判断有是/否
□ 图 ↔ 文字说明表一致（逐节点 diff）
□ 五维打分 ≥ 8
```
