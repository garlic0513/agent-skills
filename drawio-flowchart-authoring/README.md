# drawio-flowchart-authoring

> 用 draw.io（`.drawio` XML）**程序化生成**可编辑的业务流程图 / 泳道图，并做**交付前自动验收**。

## 为什么不用"手拖框"

```
手拖框：画到第 30 个节点 → 返工
程序化：写成数据（泳道/节点/连线）→ 生成 → 几何校验 → 真渲染 → 打分 → 交付
        ↑ 改一处只需改一行数据，1 分钟出全图
```

## 解决什么

| 症状 | 本技能给的解法 |
|---|---|
| 连线穿过节点框 | 走廊路由铁律 + 布局优先原则 + 几何校验脚本 |
| 图太乱、交叉太多 | 四种布局选型 + 泳道内两列 + 交叉数基线 |
| 节点太多看不清 | 自适应行距/字号公式 + 实测上限（≈34 节点/页） |
| 编号乱、跳号、倒挂 | 编号规则（步长/连续/补号）+ 交付前自查 |
| 不知道图画得好不好 | 质量五维打分卡（8 分才可交付） |
| 别人发来 .eddx 打不开 | `.eddx = ZIP` 解包 + 几何解析脚本 |
| 服务器没 GUI 无法预览 | draw.io 引擎真渲染自查（本地 http + 截图） |

## 内容结构

```
SKILL.md                   主流程与方法（七步工作流 / 样式 / 泳道 / 编号 / 布局 / 打分 / 坑库）
references/                9 篇专题（打分卡 / 布局实测 / 全展开单页 / 真渲染 / 一致性审查 / eddx 解析 …）
scripts/                   9 个可执行脚本（生成 / 校验 / 解析 / 渲染 / 多页合并）
```

## 快速开始

```bash
# 1) 写一份 spec.json（lanes / nodes / edges）
python3 scripts/drawio_swimlane.py spec.json out.drawio

# 2) 几何体检（穿框 / 压线 / 交叉 / 折点）
python3 scripts/check_lines_per_page.py out.drawio

# 3) 真渲染自查
python3 scripts/make_drawio_preview.py out.drawio
#    → 起本地 http，用浏览器打开截图，自己先看一眼
```

## 核心主张

> **流程图不是画出来的，是"定义数据 → 生成 → 几何校验 → 真渲染 → 打分"出来的。**
