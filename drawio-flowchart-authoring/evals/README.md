# 落地质量评测（evals/）

> 判断这个技能**真的有用吗**，而不是"写得像不像"。
> 建法参照 microsoft/waza 的 eval schema（file must_exist / content_patterns），
> 执行器换成 Hermes（waza 只支持 copilot-sdk，驱动不了本机 agent）。

## 为什么要有这套东西

不加技能，模型**也能画出流程图、编号也不一定错**——所以"有没有产出"根本区分不出好坏。
真正拉开差距的是**几何质量**：不加技能时线穿过节点框 50–60 处，加了技能是 0 处。

> 技能的价值不在"会不会画"，而在"画出来能不能交付"。

## 怎么跑

```bash
cd ~/.hermes/skills/productivity/garlic-drawio-flowchart-authoring

# 单跑某几条（加载技能）
python3 evals/runner.py --mode with-skill --tasks T1,T3

# A/B 对照（有技能 vs 无技能）——最能说明技能价值
python3 evals/runner.py --mode both --tasks T1,T3

# 全量
python3 evals/runner.py --mode with-skill
```

⚠️ 每条任务会真实调用一次 `hermes -z`（约 25–190 秒），全量 9 条约 15–20 分钟。
⚠️ **hermes -z 的文件工具不跟随 shell cwd**，runner 会把绝对输出目录写进 prompt（否则产物落到 `~` 下，全部 0 分）。

## 任务清单与判据

| 任务 | 考什么 | 通过判据 |
|:-:|---|---|
| T1 基础画图 | 能不能按约束出图 | 形状≥5、泳道≥2、有菱形、**穿框 0** |
| T2 编号规则 | 编号规范 | `^(\d+)` 序列严格等差（10/20/30…） |
| T3 泳道与职责分离 | 执行岗与复核岗分开 | 泳道≥2 且含"复核"泳道、穿框 0 |
| T4 判定与分支标签 | 菱形 + 是/否 | 有 rhombus 且出边标签含"是"和"否" |
| T5 修图 | 会不会诊断并修复 | 编号连续 + 无悬空连线（fixtures/broken.drawio） |
| T6 负样本 | 该不该触发 | 不产生 .drawio，且答对住宿标准 |
| T7 大页压测 | 30+ 节点压一页 | 节点≥25、穿框 0、交叉≤节点数/4 ⚠️ 常超时，见下 |
| T8 子流程调用 | 多页 + 双线框 | diagram≥2、含 `shape=process`、正文提到"第2页" |
| T9 超收短收三分支 | 三分支处置 | 边上标签含 退回 / 补发 / 改单（或修改） |

## 关键结论

```
① 技能的真实增益 = 【几何质量】（线不穿节点框），不是"会不会画图"。
   越复杂的流程差距越大：T1 差 60 处、T3 差 50 处、T9 差 30 处。
② T2/T4/T5/T6/T8 模型原生就能做对 → 这些题对"技能优化"没有信息量。
③ 原 T7 超时是【任务设计过重】（要求真渲染视觉迭代），不是能力问题：
   拆成"只查几何"后 43 个节点 178 秒就过了。
④ ⚠️ 当前技能在有效任务上已 8/8 满分 → 【没有失败样本，优化器无输入】。
   想继续优化，必须"加严判据"或"加更难的任务"，见下。
```

## 已知问题

```
① T7 会超时：30+ 节点 + 真渲染视觉自检 = 一轮闭环 3-5 分钟，改两次就超 7 分钟。
   → 建议拆成 T7a（只查几何，timeout 300s）与 T7b（视觉迭代，timeout 900s）。
② T7/T8/T9 的"无技能对照"还没跑，A/B 只覆盖了 T1-T5。
③ 判据里"交叉 ≤ 节点数/4"是经验值，不是理论值。
④ T7b（900s 视觉迭代）与 T7a 的无技能对照还没跑。
```

## 改了技能之后怎么用

```
1. 先跑一次全量 → 记下通过数与穿框数（基线）
2. 改 SKILL.md / 脚本
3. 再跑一次 → 通过数不能降、穿框必须仍为 0
4. 降了就是回归，回滚
```

## 轻量优化（evals/optimize.py）

有失败样本时可用：把失败记录喂给 DeepSeek（当 optimizer），让它出**锚点式最小补丁**（anchor + insert），
写完 `evals/optimizer-proposal.json` 等你人工确认——**不会自动改 SKILL.md**。

```bash
python3 evals/optimize.py --tasks T1,T3 --dry
```

⚠️ 现在【有技能模式 8/8 全过】→ 没有失败样本 → 优化器无素材。
要继续优化，只有两条路：
   A. 加严判据：交叉必须 0 / 字号必须 ≥7pt / 单页必须 ≥40 节点 / 图↔表必须一致
   B. 加更难任务：跨系统边界页（WMS×WCS）、状态机图、40+ 节点含 6 泳道
失败样本全部来自 without-skill 模式 —— 那是"技能的功劳证明"，不是"技能需要改的地方"。
