# 作业要素卡 · Work Element Card

> **把一项作业拆成固定维度写清楚 —— 一岗一卡、一事一卡。**

## 要解决的问题

SOP 太长（现场不看）、口头交底太随意（新人不会）、检查表太碎（只查不教）。

**缺的是一页纸：把这活儿"从哪来、谁干、凭什么干、拿什么干、怎么干、干出什么、留什么痕、出错怎么办、多久干完"一次写全。**

## 九要素（六核心 + 三必备）

```
【六核心】
① 触发条件 —— 什么事件启动这项作业
② 执行人员 —— 谁做（岗位 + 授权）
③ 输入信息 —— 拿什么开工（实物 / 单据 / 数据）
④ 具体操作 —— 怎么做（动作 + 对象 + 标准）
⑤ 输出结果 —— 做出什么（实物 / 系统 / 中间态）
⑥ 异常情况 —— 出错怎么办

【三必备】⭐
⑦ 依据标准 —— 凭什么这么做、依据什么判定"符合"
⑧ 记录留痕 —— 做了什么要留痕（输出 ≠ 凭证）
⑨ 时限频次 —— 多久做一次、多久内完成
```

## 核心亮点

- ⭐ **异常列是差异化**：同类框架（SIPOC / 5W1H）普遍缺这一维；它把"异常驱动"写进作业卡，直接对应流程图的异常分支
- ⭐ **依据 + 记录两条是审计刚需**：缺了这两条，作业卡过不了审计，也挂不上追溯链
- ⭐ **三处必须收紧的写法**：输入分三类（实物/单据/数据）｜操作写三段（动作+对象+标准）｜异常配处理人
- ⭐ **与流程图天然映射（六视图）**：触发→上游连线｜执行人→泳道｜输入→输入箭头｜操作→节点文字｜输出→输出箭头｜异常→异常分支
- 附自查清单（9 项）+ 7 个常见错误 + 填满的示例

## 什么时候用

- 写作业卡 / 岗位作业说明 / 新人培训卡（一岗一卡）
- 写 SOP / 作业指导书时先搭骨架
- 为流程图的每个节点配"说明表"（图上塞不下的细节放卡里）
- 系统上线 / 验证时做"操作确认清单"
