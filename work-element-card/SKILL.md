# 作业要素卡（九要素）

> 一句话：**把一项作业拆成固定维度写清楚 —— 一岗一卡、一事一卡。**

## 何时使用

- 写作业卡 / 岗位作业说明 / 新人培训卡（一岗一卡）
- 写 SOP / 作业指导书时先搭骨架
- 为流程图的每个节点配"说明表"（图上塞不下的细节放卡里）
- 系统上线 / 验证时需要"操作确认清单"
- 交接、外包、临时用工时需要把活儿讲清楚

## 与 SOP 的区别

```
SOP（标准操作规程）= 长文档，一章一节，给管理者与审计看
作业要素卡         = 一页维度表，给现场与新人看，照着做
⭐ 两者互补：SOP 里嵌作业卡，比纯文字更不容易漏
```

---

## 一、⭐ 要素总览（九要素 = 六核心 + 三必备）

```
【六核心】
① 触发条件　—— 什么事件启动这项作业
② 执行人员　—— 谁做（岗位 + 授权）
③ 输入信息　—— 拿什么开工（实物 / 单据 / 数据）
④ 具体操作　—— 怎么做（动作 + 对象 + 标准）
⑤ 输出结果　—— 做出什么（实物 / 系统 / 中间态）
⑥ 异常情况　—— 出错怎么办

【三必备】⭐
⑦ 依据标准　—— 凭什么这么做、依据什么判定"符合"
⑧ 记录留痕　—— 做了什么要留痕（输出 ≠ 凭证）
⑨ 时限频次　—— 多久做一次、多久内完成

（可选补充：前置条件 / 权限审批 / 上下游 —— 按需再加）
```

### 为什么是这三条最重要

```
⑦ 依据标准：合规场景里"没有依据的操作"就是缺陷项；
   也是追溯链（需求→设计→执行→验证）的锚点。

⑧ 记录留痕：⭐ 铁律"没记录 = 没做过"。
   输出结果 ≠ 记录凭证 —— 必须写清【留什么痕、留哪里、谁签字】。

⑨ 时限频次：影响排班、绩效、时效性；也是现场改善的抓手。
   例："到货后 2 小时内完成初检"。
```

## 二、⭐ 每个要素填什么 + 追问句

| # | 要素 | 填什么 | 追问 |
|:-:|------|--------|------|
| ① | 触发条件 | 什么事件/时点启动 | 谁触发？系统触发还是人？可能漏触发吗？ |
| ② | 执行人员 | **岗位 + 授权**（不写人名） | 谁有权限？要不要复核人？ |
| ③ | 依据标准 | 法规 / 需求条款 / SOP（含版本号）/ 质量标准 / 系统配置 | 凭什么判定"符合"？依据文号+版本是什么？ |
| ④ | 输入信息 | ⭐ 分三类：**实物 / 单据 / 数据** | 少一样能不能开工？上游谁给？ |
| ⑤ | 具体操作 | ⭐ 三段式：**动作 + 对象 + 标准** | 怎样算做完？标准是多少？ |
| ⑥ | 输出结果 | 实物结果 + 系统结果 + 中间态 | 下游谁接收？ |
| ⑦ | 记录留痕 | 系统记录 / 纸质表单 / 签字 / 附件 / 审计追踪 | 留什么？留在哪？审计时怎么调出来？ |
| ⑧ | 异常情况 | 异常清单 → ⭐ **处理方式 + 去向 + 处理人** | 谁处理？升级到谁？留什么痕？ |
| ⑨ | 时限频次 | 频次 + 单次时限 + 超时后果 | 多久一次？超时怎么办？ |

### ⚠️ 三处必须收紧（否则落不了地）

```
① "输入信息" 拆成【实物 / 单据 / 数据】三类
   → 混在一起最容易漏（一次收货往往同时涉及三类）

② "具体操作" 写成【动作 + 对象 + 标准】
   ✗ "核对、扫描、录入、确认"
   ✓ "扫描 托盘码 → 系统显示物料信息一致；
      录入 到货数量 → 与送货单差异为 0"

③ "异常情况" 必须配【处理方式 + 处理人】
   → 只列异常不闭环 = 把问题丢回现场
```

## 三、⭐ 与流程图的映射（六视图）

```
作业卡的每一行，都对应流程图上的一个视觉元素：

触发条件 → 上游连线 / 入口事件
执行人员 → 泳道（岗位）
输入信息 → 输入箭头
具体操作 → 节点文字
输出结果 → 输出箭头
异常情况 → 异常分支（菱形）+ 旁路

⭐ 用法：图上只写动作，卡里写全九要素
   → 解决"图上塞不下"的问题；一个节点配一张卡
```

## 四、放到同类框架里定位

| 框架 | 要素 | 缺什么 |
|------|------|--------|
| 5W1H | What/Why/Who/When/Where/How | 无输入输出、无异常 |
| SIPOC | Supplier/Input/Process/Output/Customer | 无异常、无触发 |
| IDEF0（ICOM） | Input/**Control**/Output/**Mechanism** | 无异常 |
| 人机料法环 | Man/Machine/Material/Method/Environment | 无流程时序 |
| ⭐ **作业要素卡** | 触发/执行人/依据/输入/操作/输出/记录/异常/时限 | —— |

> 六要素 ≈ SIPOC 的输入输出 + 5W1H 的行动者 + **独有的异常列**；
> 升级后补上了 IDEF0 的 **Control（依据）** 与实务必需的 **记录留痕**。

---

## 五、4 类用法

```
① 流程图节点的说明表（图上写动作·卡里写全要素）
② SOP / 作业指导书的骨架（九要素直接变九段）
③ ⭐ 新人培训卡（一岗一卡，照着做）
④ 系统上线 / 验证的"操作确认清单"
   每个要素 = 一个功能点 → 可直接做操作确认项
   （依据标准 → 追溯需求条款；记录留痕 → 审计追踪验证）
```

## 六、示例：收货作业（制造业/供应链场景）

| 要素 | 内容 |
|------|------|
| ① 触发条件 | 采购物料实际到货（供应商送达收货区） |
| ② 执行人员 | 仓管员 / 授权收货人员（复核人：仓库主管） |
| ③ 依据标准 | 收货 SOP（含版本号）· 系统主数据配置（是否称重/是否供应商管理/储存条件）· 收货质量标准 |
| ④ 输入信息 | **实物**：物料、容器/托盘<br>**单据**：采购订单、送货单、物料标签、厂家检验报告<br>**数据**：系统入库单、供应商主数据、物料主数据 |
| ⑤ 具体操作 | ①核对 送货单与采购订单 → 供应商/品名/规格/数量一致<br>②扫描 托盘码/物料码 → 系统带出物料信息一致<br>③录入 到货数量/厂家批号/生产日期/效期 → 与实物一致<br>④确认 收货 → 生成库存（状态：待检） |
| ⑥ 输出结果 | **实物**：物料入待检区<br>**系统**：收货记录、库存（待检）、入库单明细更新<br>**中间态**：异常时生成待处理任务 |
| ⑦ 记录留痕 | **系统**：收货记录（操作人/时间/数量）、审计追踪<br>**纸质**：送货单签字、初检记录、检验申请单 |
| ⑧ 异常情况 | 数量不符 → 让步接收（质量批准）或拒收 + 生成收货异常记录<br>错料 → 拒收 + 通知采购<br>破包 → 拒收/让步（评估污染风险）<br>无订单 → 拒收/暂存待确认<br>**处理人**：仓管员 + 质量 |
| ⑨ 时限频次 | 每次到货一次；到货后 2 小时内完成初检；超时 → 物料滞留待检区并上报主管 |

## 七、自查清单（填完过一遍）

```
□ 触发条件写的是"事件"，而不是模糊词（如"需要时"）？
□ 执行人员写的是【岗位】而不是具体人名？
□ 依据标准写了【文号 + 版本】吗？（合规场景必须）
□ 输入信息三类都考虑了吗（实物/单据/数据）？
□ 具体操作是"动作+对象+标准"三段式吗？
□ 输出结果区分了实物/系统/中间态吗？
□ 记录留痕写了【留什么·留哪里·谁签字】吗？
□ 异常情况每条都配了【处理方式 + 处理人】吗？
□ 时限频次写了数字吗（而不是"及时"）？
```

## 八、常见错误

| 陷阱 | 后果 | 正解 |
|------|------|------|
| 只写动词不写标准 | 新人不知道怎样算做完 | 动作+对象+标准三段式 |
| 不写依据 | 合规场景=缺陷项；无法追溯 | ⭐ 写文号+版本 |
| 不写记录 | 审计时"等于没做" | ⭐ 写留什么/留哪里/谁签 |
| 异常只列不闭环 | 问题丢回现场 | 异常 + 处理方式 + 处理人 |
| 执行人写成人名 | 人员变动即失效 | 写岗位 + 授权 |
| 时限写"及时" | 无法考核、无法改善 | 写具体数字 |
| 一张卡塞太多作业 | 没人看 | ⭐ 一事一卡 |
