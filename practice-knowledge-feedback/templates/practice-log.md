# 实践日志（Practice Log）

> 用途：把「经历」变成「经验」。每天 5 分钟，一个月后回看能看到能力曲线。
> 原则：写事实，不写感受；写判断依据，不写"我觉得"。

---

## 日志模板（复制这一段用）

```markdown
## YYYY-MM-DD ｜ 场景：____（如：客户现场调研 / 系统配置 / 客户问答）

**① 今天我做了什么**（客观事实·1-3 条）
- 
- 

**② 我当时的判断 / 做法**
- 判断：
- 依据：（为什么这么想）
- 做法：

**③ 结果如何**
- [ ] 完全正确　[ ] 部分正确　[ ] 错了
- 实际结果：

**④ 反馈来自谁**
- 师傅 / 同事 / 客户 / 系统结果 / 数据
- 反馈内容：

**⑤ 修正后的理解**（一句话）
- 

**⑥ 下次怎么做**（具体到动作）
- 
```

## 每周复盘（周五 15 分钟）

```markdown
## YYYY 第 N 周复盘

**本周做成的 3 件事**
1. 
2. 
3. 

**本周犯的错 / 卡点**（⭐ 最有价值的部分）
1. 
2. 

**抽象出的方法**（把具体经验升级成可复用的规则）
- 例："客户说'看情况'时，要追问三个判断条件：什么情况下 A，什么情况下 B，边界在哪"
- 

**下周要刻意练的一件事**（能力边缘）
- 
```

## 每月回看（月底 30 分钟）

```markdown
## YYYY-MM 月度回看

**我现在的技能阶段**（Dreyfus 模型自评）
- [ ] 1 新手（靠规则）　[ ] 2 高级新手（靠经验）
- [ ] 3 胜任者（能规划）　[ ] 4 精通者（直觉）　[ ] 5 专家

**判断依据**：本月我做过哪些"没有现成规则可依"的判断？

**能力公式自检**
| 项 | 我的现状 | 下一步 |
|---|---|---|
| 知识 | 学了什么 | 还缺什么 |
| 实践 | 做了哪些真活 | 哪些环节还没碰过 |
| 反馈 | 找谁要过反馈 | 谁还能给我反馈 |

**下月重点**（只写 1-2 件）
- 
```

---

## 使用要点

```
① ⭐ 当天写，别攒（隔天写会丢失细节和判断依据）
② ⭐ "判断依据"是核心——没有它，日志只是流水账
③ 每周必须抽象出 1 条方法（这是外化 SECI 的关键动作）
④ 每月必须自评一次阶段（看清自己在哪、下一步该练什么）
⑤ ⚠️ 反馈要主动要，不要等（师傅不会主动告诉你哪里错了）
```
