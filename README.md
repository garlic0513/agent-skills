# 认知框架法 · Cognition Framework Method

> **在提出疑惑之前，要表达疑惑；在表达疑惑之前，要觉察疑惑。**
> —— 一个关于「如何知道该问什么」的方法论

---

## 项目简介

认知框架法（Cognition Framework Method）是一套面向**陌生领域现场认知**的通用方法论。

它解决一个被普遍忽视的问题：**新手面对陌生系统时的真正瓶颈，不是"问不好"，而是"不知道自己不知道什么"**。没有认知框架，就没有参照物——疑惑不会浮现，提问无从谈起。

本方法将这一洞察与认知科学、学习科学的经典理论结合，形成可执行、可复用的完整流程：从**觉察已知**（连环拷问挖掘既有认知）到**觉察未知**（先行组织者建立框架），最终实现精准提问与有效学习。

## 核心思想

```
觉察已知（拷问挖掘）  ×  觉察未知（框架对照）
   "我知道什么"            "我不知道什么"
        ↓ 合并 ↓
   完整认知地图 → 精准提问 / 有效求助 / 高效学习
```

## 方法流程（5 步）

| 步骤 | 名称 | 作用 |
|------|------|------|
| ① | 拷问分层（Grill-Me） | 连环提问挖掘已知——产出「我知道 / 我以为我知道 / 我不知道」三层清单 |
| ② | 建框架（先行组织者） | 对未知区域建立"系统应该有什么"的认知地图 |
| ③ | 现场对照（5 问清单） | 实物与框架对照——差异即疑惑 |
| ④ | 有效求助 | 拍照 + 标注 + 结构化表达——与 AI 协作形成共识图 |
| ⑤ | 元认知升级 | 框架迭代——自我监控增强——达克效应消退 |

## 理论根基

| 理论 | 与本方法的关系 |
|------|---------------|
| 元认知（Flavell） | 训练对"自己知道/不知道什么"的监控 |
| 达克效应（Dunning-Kruger） | "不知道自己不知道"的正式名称 |
| 未知的未知（Rumsfeld） | 框架将无法提问的区域转化为可问 |
| 先行组织者（Ausubel） | 认知框架卡的直接理论基础 |
| 图式与认知冲突（Piaget） | 差异 → 冲突 → 疑惑 → 学习 |
| 认知脚手架（Vygotsky） | 框架让新手够到最近发展区 |
| 生产性困惑 | 困惑是学习的起点，而非障碍 |
| 问题驱动学习（PBL） | 好问题 = 学习引擎 |
| 苏格拉底式提问 | 连环追问让人自己发现盲区 |

## 应用场景

- **陌生领域接触**——带着框架卡对照实际，差异自动浮现
- **模糊任务开工前**——先拷问分层，再动手，一次做对
- **学习新领域**——先建"应该有什么"的地图，再对照阅读
- **教学与带新人**——让对方自己发现疑惑，比直接讲授更有效

## 使用方式

将 `cognition-framework-method/` 目录放入 agent 的 skills 目录：

```bash
# Hermes

# Claude Code
.claude/skills/
```

或直接阅读 [SKILL.md](cognition-framework-method/SKILL.md) 与 [框架卡模板](cognition-framework-method/templates/cognition-framework-card.md) 手动使用。

## 配套交付物

`cognition-framework-method/templates/cognition-framework-card.md` —— 认知框架卡模板：面向任意设备/系统，7 个字段（是什么 / 看什么 / 关键部件 / 管道连接 / 显示状态 / 5 问清单 / 安全边界），现场认知即取即用。
