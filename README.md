# Agent Skills · 通用方法论与工具集

> 六个关于「**怎么想**」「**怎么学**」「**怎么画**」「**怎么问**」「**怎么记**」「**怎么落**」的通用方法论 —— 不依赖特定行业，可直接迁移到任何新领域。
> 外加一个把方法论**真正落成可交付物**的执行工具。

---

## 📚 技能列表

### 1. 认知框架法 · Cognition Framework Method

> **在提出疑惑之前，要表达疑惑；在表达疑惑之前，要觉察疑惑。**

面向**陌生领域认知**的通用方法论。解决一个被普遍忽视的问题：

**新手面对陌生系统时的真正瓶颈，不是「问不好」，而是「不知道自己不知道什么」。**

- 5 步流程：拷问分层 → 建框架 → 对照实际 → 有效求助 → 元认知升级
- 融合认知科学与学习科学（元认知 / 达克效应 / 先行组织者 / 图式冲突 / 生产性困惑 / PBL）
- 📂 [`cognition-framework-method/`](./cognition-framework-method/)

### 2. 实践 · 知识 · 反馈 · Practice Knowledge Feedback

> **知识让你「知道」，实践让你「会做」，反馈让你「做对」。三者相乘，缺一为零。**

关于**能力如何真正长出来**的框架。回答两个高频困惑：

- 为什么学了很多却做不出来？
- 为什么做了很久却原地踏步？

```
能力 = 知识 × 实践 × 反馈
```

- 三个经典理论：Polanyi 隐性知识 · Dreyfus 技能五阶段 · 野中郁次郎 SECI 知识转化螺旋
- 6 条方法 + 能力诊断表（五问自测）+ 反馈话术模板 + 实践日志（日/周/月三层）
- 📂 [`practice-knowledge-feedback/`](./practice-knowledge-feedback/)

### 3. 全分支流程图工作法 · Full-Branch Flowchart Method (FBF)

> **把流程图当成决策树来画 —— 预置客户所有可能的分支，会上和客户一起「剪枝」。**

面向**流程梳理与需求确认**的方法。解决传统做法的痛点：

**让人指出「缺什么」很难，让人回答「要不要」很容易。**

```
传统：我方画一条标准流程 → 客户提差异 → 改 → 再提 → 再改（3-5 轮）
本方法：我方预置全分支树 → 会上客户剪枝 → 一轮定稿
```

- 四步法：建分支库 → 画全分支树 → 会上剪枝 → 定稿
- ⭐ **绘制五条铁律**：先定泳道→再排节点→最后连线；全局顺序定 y；菱形左右・矩形上下；水平走行间隙／垂直走泳道走廊（防穿框）；待确认选项放最右侧面板
- 18 条通用判定点分支库 + 树状编号体系（1.3.a）+ 实施坑清单
- 📂 [`full-branch-flowchart-method/`](./full-branch-flowchart-method/)

### 4. 需求调研四维记录法 · Research 4D Method

> **把对方口头说的需求，翻译成可执行的需求，并标出还没定的部分。**

面向**需求调研**的记录框架，四维按固定顺序推进：

```
现状 AS-IS → 目标 TO-BE → 差异 GAP → 待确认 OPEN
（现在怎么干） （想怎么干）  （能不能干） （还缺什么·谁定）
```

- ⭐ 每个维度配「追问清单」——现场照着问，问出真话
- ⭐ 差异必须三选一：能（标准）/ 部分（需配置）/ 不能（需定制）——报价与工期依据
- ⭐ 待确认必须带责任人和期限
- 会后自动出三张清单：需求清单 / 选项清单 / 风险清单
- 📂 [`research-4d-method/`](./research-4d-method/)

### 5. 会议纪要写法 · Meeting Minutes That Work

> **纪要的目的不是「记录」，而是【决策留痕 + 行动落地 + 事后可查】。**

关于**会议如何变成凭证**的方法。一份纪要写得漂亮不重要，**可执行 + 可追溯**才重要。

- ⭐ 6 条质量标准：议题必有结论 / 待办必有责任人期限 / 区分事实观点决策待办 / 保留关键原话 / 24h 内确认 / 可追溯
- 「四不写」清单 + 8 段结构（议题→决议→行动→待确认→附件→下次安排）
- 会前 10 分钟准备 / 会中边听边填 / 会后当天闭环
- 📂 [`research-meeting-minutes/`](./research-meeting-minutes/)

### 6. 作业要素卡（九要素）· Work Element Card

> **把一项作业拆成固定维度写清楚 —— 一岗一卡、一事一卡。**

关于**事情怎么落到岗位上**的方法。SOP 太长（现场不看）、口头交底太随意（新人不会）、检查表太碎（只查不教）——缺的是一页纸。

```
六核心：触发条件 / 执行人员 / 输入信息 / 具体操作 / 输出结果 / 异常情况
三必备：依据标准 / 记录留痕 / 时限频次
```

- ⭐ **异常列是差异化**：同类框架（SIPOC / 5W1H）普遍缺这一维
- ⭐ **依据 + 记录是审计刚需**：缺了这两条，作业卡过不了审计、挂不上追溯链
- ⭐ **与流程图天然映射（六视图）**：触发→上游连线｜执行人→泳道｜输入→输入箭头｜操作→节点文字｜输出→输出箭头｜异常→异常分支
- 自查清单（9 项）+ 7 个常见错误 + 填满的示例
- 📂 [`work-element-card/`](./work-element-card/)

### 7. Drawio 流程图生成与验收 · drawio-flowchart-authoring（执行工具）

> **流程图不是画出来的，是「定义数据 → 生成 → 几何校验 → 真渲染 → 打分」出来的。**

把上面第 3 条（全分支流程图工作法）**真正落成可交付文件**的工具技能。解决手工画图的三类硬问题：

```bash
# 1) 写成数据（泳道 / 节点 / 连线）→ 一条命令出图
python3 scripts/drawio_swimlane.py spec.json out.drawio

# 2) 几何体检（穿框 / 压线 / 交叉 / 折点）
python3 scripts/check_lines_per_page.py out.drawio

# 3) 真渲染自查（服务器无 GUI 也能看成品）
python3 scripts/make_drawio_preview.py out.drawio
```

- **治"线太乱/穿框"**：四种布局策略 + 走廊路由铁律（水平走全局行间隙、垂直走泳道走廊）+ 几何校验脚本
- **治"节点太多看不清"**：全展开单页自适应公式（节点数→行距→字号的数学关系），实测可读上限 ≈ 34 节点/页
- **治"编号乱飞"**：编号规则（步长统一 / 连续无断号 / 顺序不倒挂 / 插节点用中间号）
- **治"不知道画得好不好"**：⭐ **质量五维打分卡**（正确性 / 完整性 / 可读性 / 规范性 / 可维护性，8 分才可交付）+ 12 条快速自检 + 12 条高频缺陷库
- **治"别人发的 .eddx 打不开"**：`.eddx = ZIP` 解包提取文字与泳道几何
- 📂 [`drawio-flowchart-authoring/`](./drawio-flowchart-authoring/)

## 🧭 七个技能的关系

```
认知框架法          →  想：面对陌生领域，我该怎么看见自己的盲区、提出有效问题
实践·知识·反馈      →  学：知道了怎么问之后，我怎么真正学会
全分支流程图工作法  →  画：怎么把业务"一条线"变成"一棵树"，让对方做选择题
需求调研四维记录法  →  问：见到人之后，我怎么把"他说的"变成"要做的"
会议纪要写法        →  记：谈完之后，我怎么把"讨论"变成"可追溯的凭证"
作业要素卡          →  落：定下来之后，我怎么把"一个节点"落成岗位能照着做的作业卡
drawio 画图工具     →  做：上面"画"和"落"的结论，怎么变成一张能评审、能交付的图
```

**串起来是一条完整链路：**

```
先看见自己的盲区（认知）
   → 建立学习闭环（实践·反馈）
      → 把业务画成全分支树（流程）
         → 到现场把需求问清楚、记准确（四维）
            → 把结论固化成可追溯的凭证（纪要）
               → 把定稿的每一步落到岗位作业（作业要素卡）
                  → 全部落成可交付、可打分验收的图（drawio 工具）
```

任一环缺失都会漏：只学不问 → 学不到真需求；只问不画 → 讨论没有落点；只画不记 → 结论留不下来；只记不落 → 文档很漂亮但没人照着做；只落不定稿 → 图很漂亮但没人认。

**交叉引用表：**

| 上游产出 | 下游动作 |
|---------|---------|
| 四维记录法的「差异 GAP」 | → 全分支图的「可选分支」 |
| 四维记录法的「待确认 OPEN」 | → 全分支图的「待确认菱形」 |
| 全分支图「剪枝结果」 | → 纪要的「决议事项」 |
| 全分支图「剪掉的分支」 | → 纪要留痕：「某人确认不需要 XX」 |
| 流程图的每个节点 | → 作业要素卡（九要素） |
| 作业要素卡的「异常情况」 | → 流程图新增的异常分支（反向反馈） |
| 全分支图的分支与布局 | → drawio 工具的「布局策略 / 编号规则」 |
| drawio 的「质量五维打分」 | → 交付前的合格判定（8 分以上） |

## 🔧 使用方式

每个技能目录下都有 `SKILL.md`（方法论全文）与 `README.md`（速览）。把技能目录复制到你所用 agent 的技能目录即可：

```
Hermes:       ~/.hermes/skills/
Claude Code:  ~/.claude/skills/
```

格式对齐 [Agent Skills 规范](https://agentskills.io/specification)：`name` + `description` frontmatter，Markdown 正文。

## 🎯 适用范围

前六个方法都**不依赖特定行业**——软件开发、制造、医药、咨询、科研均适用。文中出现的行业示例仅为说明用途，方法论本身是通用的。

第七个是**执行工具**，需要 `python3`；其中「真渲染自查」一步需要一个浏览器（headless 即可），其余步骤纯命令行。
